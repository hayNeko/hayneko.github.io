# Hayneko

个人站点。**terminal / 科技风**：黑底白字 + 红绿蓝点缀，背景是一块**字符网格** ——
加载后先铺满一屏字符、开场一圈大涟漪，随后该拼字的字符**一格一格跳**到自己的位置：
上方是一颗 **3D ASCII 星球（带行星环，正面朝向鼠标）**，中间一行 `MIKU ICHINOSE`，
下面跟着当前路径（`~/home`）。换页时文字整体打乱重排，星球稳定不动。
无刷新页面切换，底部 Dock，还有一个真的能用的终端。

> 本站原先是 `hayneko.github.io/` 子目录，现在整个搬到了仓库根目录，
> `index.html` 就是入口。原先放在根目录的那版 `dsh://terminal` 原型已归档到
> `archive/dsh-terminal/`（见 `archive/README.md`），没有删除。

## 运行

必须通过 HTTP 服务器打开 —— 路由与语言包都依赖 `fetch`，直接双击 `index.html`
（`file://`）会被浏览器拦住。

**最省事的方式：双击仓库根目录的 `serve.cmd`**，它会起一个服务并自动打开浏览器：

```
http://127.0.0.1:8123/
```

手动起也可以：

```bash
python -m http.server 8123 --bind 127.0.0.1
```

> ⚠️ **服务器不能关。** 关掉之后页面因为浏览器缓存看着还在，
> 但点任何**新**链接（物理实验室、资源下载）都会报 `ERR_CONNECTION_REFUSED` ——
> 因为它们要真的去请求服务器。

旧站原型仍可单独打开：

```bash
python -m http.server 8125 --directory archive/dsh-terminal
```

## 视觉：三色 + ASCII 背景

主色仍是黑底 + 白字，`--red` / `--green` / `--blue` 三个语义色负责点缀与状态
（深色主题 `#ff4d5a` / `#3ce07b` / `#4d9dff`，浅色主题压深一档），顶栏的「强调色」开关
在三者之间切换（`data-accent`），终端里对应 `accent red|green|blue`。

**背景是一块字符网格**（`scripts/geometry-bg.js`）—— 不是"拿字符当 sprite 的矢量动画"，
而是**离散**的那种：终端里每个字符占一个整数行列，没有浮点坐标，也不能半格移动。
"移动"= 上一帧在 (row, col) 的字符消失、下一帧在 (row+1, col) 出现。
代码里对应两处：

- 绘制前一律 `gx = Math.round(p.x / cell) * cell`（吸附到**字符格**，不是像素）；
- 装配进度也量化成整数步：`Math.floor(k * p.steps) / p.steps`，
  `p.steps = 路径长度 / 格宽`，于是一步跨一格，是跳格而不是平滑滑动。

### 画面构成（自上而下，整体居中）

| 元素 | 说明 |
| --- | --- |
| **3D ASCII 星球 + 行星环** | 球面按纬度分带撒点（`buildPlanet()`），法线与光向点积决定字符与亮度，背面剔除 + 画家算法排序；两圈环在赤道面上（半径 `1.72R / 2.08R`），被球挡住的那半圈会挖掉。**正面朝向鼠标** |
| **`MIKU ICHINOSE`** | 离屏栅格化的等宽字形，居中；字面 + 2 层右下方向的暗影 |
| **当前路径** | 掩码的第二行（`~/home` / `~/labs` …），从 `Router.path()` 读，跟着路由走 |
| 散字 | 满屏游走，装配完成后压暗 |

### 三段式

1. `fill` —— 页面加载后先**铺满一屏字符**（散字按"抖动网格"落位，不是随机撒，免得一块一块），
   开场先来一圈**大涟漪**（起始半径 = 视口短边 × 0.18，扫过时把字符推开一格再亮一下）；
2. `assemble` —— 该去拼字的字符沿**随机曲线**跳着归位。曲线仍是二次贝塞尔
   （控制点在起终点连线的中垂方向随机外扩 16%~40% 屏宽），但**位置逐帧吸附到格点**，
   所以看上去是一串离散的落点，不是一条光滑轨迹；
3. `lock` —— 锁成 3D 字型：字面 + 2 层暗影，每层**整数格**向右、向下各错 1 格
   （`LAYER_DX = LAYER_DY = 1`），就是传统 ASCII 立体字那种右下方向的投影。
   字型静止朝向 `REST_YAW = 0`、`tilt = 0`；每 9s 还有一条扫描带自上而下扫过。

> **文字必须严格轴对齐。** 早先留了 `REST_YAW = 0.26`，字面会被 `cos(yaw)` 横向压掉 3% ——
> 86 列里有若干相邻列被压到同一格，字上就出现一排缺口，看着凹凸不平。
> 现在立体感完全由暗影层的整数格偏移提供，字面一格不差（实测同一掩码行不会落到两行、
> 同一列不会落到两列：`splitRows = 0 / splitCols = 0`）。

### 朝向鼠标：物件正面指着指针

星球（以及打开 `POINTER_FOLLOW` 时的文字）朝向指针，符号是推导出来的：

- `yaw = −pointer.x × 0.62`：鼠标在右边 → 球面**右转**；
- `tilt = +pointer.y × 0.34`：鼠标在上边 → 球面**抬头**。

> 这两个正负号一开始是反的（鼠标往右球面往左、鼠标往上球面低头），
> 因为把"正面法线朝观察者"当成了 `+z`。z 在本文件里是**离观察者越来越远**的方向，
> 所以正面法线是 `−z`：代入旋转矩阵 `(x' = x·cos + z·sin, z' = −x·sin + z·cos)` 得到
> `normal = (−sin yaw, sin tilt, −cos·cos)` —— 想让法线指向鼠标那一侧，就得上面那两个符号。
> 实测：鼠标移到右上角 `yaw = −0.59 / tilt = −0.28`，移到左下角 `yaw = +0.57 / tilt = +0.31`。

> 文字部分即使打开 `POINTER_FOLLOW` 也不吃 `tilt`（保持 0）：字符吸附在格子上，
> 一旦剪切超过半格整行字就会翻行。

### 切路由：文字打乱重排，星球不动

路由换页会派 `route:changed`，`GeometryBG` 收到后：重新栅格化掩码（路径那行变了）→
重建文字目标 → `scrambleText()` 把所有文字粒子扔回满屏随机格、`lock` 清零、重新计时。
星球不在粒子系统里（它每帧按参数现算），所以完全不受影响。

> 这里踩过一个坑：粒子的 `delay` 原本是相对时间轴 0 点算的，换页那一刻 `t` 已经跑了几千毫秒，
> 新粒子第一帧就 `k = 1` 直接到位 —— 打乱动画根本看不见。现在 `delay = relNow() + 随机`。

### 字形是"栅格化"来的

早先试过 5x7 点阵 + 按笔画挑 `|` `-` `/` `\` `+` 画字，好看但只能算"线框图"。
现在换成**真字形**（`rasterizeMask()`）：

1. 在离屏 canvas 上用**浏览器自带的等宽字体**（`ui-monospace` / Menlo / Consolas 那一档）把
   `"MIKU ICHINOSE"`（**居中**）和它下面的路径（小一号、也居中）画进去，
   主行字号由"整行铺满 cols 格"反推；
2. `getImageData` 取 alpha，`>=128` 的像素就是一个字符格；再裁掉四周空白，得到字形掩码
   （1440 宽实测 86×21 格：主行 8 行 + 缝 + 路径 7 行）；
3. 字号刻意**比字格小一圈**：`fontPx = cell × 0.92`，于是字符宽约 0.55 格、左右留出
   约 5.6px 的空隙 —— 之前 `fontPx = cell × 1.26` 时字符挨在一起，串成一片看不清；
4. 每格按**左上打光的明暗**（`shade = 1 - y×0.42 - x×0.16`）挑字符与不透明度：

| 层 | 字符梯度 | 不透明度 |
| --- | --- | --- |
| 字面（第 0 层） | `RAMP_FACE = @ # % & $ * +` —— 最淡也是 `+`，字形永远实心 | 0.40~0.84 |
| 暗影（第 1~2 层） | `RAMP_SOFT`，可以一路淡到 `',` | 0.12~0.36，逐层 ×0.6 |
| 路径那行 | 同样只取 `RAMP_FACE` 的前几档 | 0.60（更暗但不虚） |

> **两张字型的坑**：① 字面如果用完整梯度，斜笔画会掉成 `.`，字看起来是空心的 ——
> 所以字面单独一套"最淡也是 `+`"的梯度，明暗交给**颜色深浅**表达；
> ② 暗影层如果又少又远（每层退 2 格），旋转/错位时就成了断断续续的拖影 ——
> 现在**每层只错 1 格左右**（横向由 `DEPTH_STEP` 决定，纵向 0.75 格），是一整条贴着字形的暗带。

**颜色跟着 accent 走**：`readAccent()` 用 `getComputedStyle` 读 `--accent`，
顶栏切强调色或终端跑 `accent red|green|blue` 时（都会派 `accent:changed`）重读一次，
于是字型、侧面、Hero 的 caret 是同一个色。实测切到红是 `rgb(253,79,93)`、
切到蓝是 `rgb(77,157,255)`（直接从画布像素里读出来的）。

### 位置：整组在页面中间

星球 + 文字 + 路径是一整组，**整体垂直居中**（组心在 `0.47h`），水平居中于视口。
`originX / originY / planetCY` 都取整到**整格**，静止时每个字符正好压住一个格子。
竖排预留高度里，星球的半高按 `1.18R` 算（环几乎侧对着看，竖直方向被压扁），
不然环会白白占掉一大块。

### 背景不能和正文抢

上一轮重点修过这个问题（亮背景 + 满屏大字时正文几乎读不出来）。现在字型搬到左上角之后：

1. **整块只有 99×9 格**（约 820×75px 的一条），不再是铺满屏幕的大字；
2. **散字退场**：装配完成后散字整体压暗 55%，不再一直在正文后面抖；
3. **面板加深**：卡片/文件行/页脚等"正文容器"的底色不透明度调高（深色 0.88、浅色 0.95）；
4. **那枚「系统在线」标签给了实底**（`.eyebrow` 深色 `rgba(6,10,15,.78)`、浅色 0.92）——
   它现在正好压在字型上，原来是近乎透明的，字会互相打架。

> 自检办法：直接读 `#bg-canvas` 的像素，算**合成亮度**（`rgb 均值 × alpha`，
> 注意 `getImageData` 给的是非预乘颜色）。

### 调这块踩过的坑

| 坑 | 症状 | 原因 |
| --- | --- | --- |
| 字面铺多种随机字符 | 字形明明是对的，看上去却是噪声 | 眼睛没法把形状各异的字符归成一个笔画 → 字面单独一套"最淡也是 `+`"的梯度 |
| 暗影层太亮 | 和字面糊成一片雾，字形反而看不清 | 侧面不透明度要压到字面的 1/3 上下 |
| 透视太强（焦距 200 格） | 深处几层往画面中心收，字糊成一团 | 焦距给到 900 格（近似正交） |
| 带 `tilt` 又吸附到格 | 整行字被撕开、翻到隔壁行 | 行的剪切超过半格就翻行 → 关掉鼠标跟随时 `tilt` 固定为 0 |
| 模型坐标写 `celly - rows / 2` | 字这儿凸一块、那儿凹一块 | 掩码 86×21，行数是**奇数**，`rows / 2 = 10.5` 让每一行正好压在 `round` 的半格边界上 → 改用 `Math.floor` |
| 字面带一点 `REST_YAW` | 字上出现一排缺口 | `cos(yaw)` 把相邻列压到同一格 → 字面改成严格轴对齐 |
| 一行太长被截断 | 命令字幕跑到屏幕外 | 字幕超过 62 字就截断，窄屏另有短版命令 |

性能：桌面端总字符约 1850 个（目标 950 + 散字），每个一次 `fillText`；
DPR 上限 1.5；页面不可见时暂停；
系统开了「减少动态效果」时只画一帧静态成品，完全不跑 RAF。

## 性能分级：移动端主动减特效

`scripts/perf-tier.js` 是**最前面一个阻塞脚本**（几百字节、只做同步探测、不碰 DOM），
在动效层之前把设备分成三档，并把结果摊成一张预算表；动效层只读表做减法，自己不判断设备。

**判据**（UA + 能力探测）：

| 信号 | 取值 |
| --- | --- |
| UA / client hints | `Android|iPhone|iPod|Mobile|HarmonyOS`；iPadOS 13+ 的 UA 与 macOS 相同，靠 `maxTouchPoints > 1` 区分 |
| 硬件 | `navigator.hardwareConcurrency`、`navigator.deviceMemory` |
| 网络 | `navigator.connection.saveData` / `effectiveType` |
| 交互 | `(pointer: coarse)`、`(hover: none)` |
| 视口 | `innerWidth/innerHeight`、`devicePixelRatio` |
| 偏好 | `MotionPref.reduced`（系统“减少动态效果”） |

> **client hints 只能当正向信号。** 桌面浏览器、以及 UA 被覆盖/伪装的场景里，
> `navigator.userAgentData.mobile` 都会是 `false` —— 拿它当权威会把真手机判成桌面。
> 实测无头 Edge 用 CDP 覆盖成安卓 UA 时它就返回 `false`，所以现在是两种信号取“或”。

打分（每项越弱越加分，≥3 为 mid、≥7 为 low；省流 / 单核 / ≤1G 内存直接不加载背景）：

| 档 | 粒子倍率 | 掩码列数 | 环数 | DPR 上限 | 帧率上限 | 扫描带 / 涟漪 / 切页打乱 |
| --- | --- | --- | --- | --- | --- | --- |
| `high` | 1 | 92 | 2 | 1.5 | 不限 | 全开 |
| `mid` | 0.62 | 76 | 1 | 1.25 | 不限 | 全开 |
| `low` | 0.32 | 60 | 1 | 1.0 | 30 | 全关（切页改成快速补位，不做漫游） |

**按需加载**：`index.html` 里不再静态引 `geometry-bg.js`，而是先问一句 `PerfTier.budget.background` ——
省流 / 单核 / ≤1G 内存就**根本不加载**这 30KB（`app.js`、`router.js`、`dock.js` 调 `GeometryBG` 时
都做了存在性判断，所以不加载也一切正常）；其余情况等 `DOMContentLoaded` 再注入，
那时 `defer` 脚本已经跑完、顺序确定，而背景本来就要等启动屏收起才开始。

**运行期再降一级**：预算表管的是“这台设备大概什么档次”，`geometry-bg.js` 里的 `checkPerf()` 管的是
“这一页此刻到底跑不跑得动” —— 预热 40 帧后按 50 帧一窗统计平均帧耗时，连续两窗都超过 32ms 就降一级：

1. 散字减半 + 星球点变稀；
2. 帧率封顶 30 + 停自转；
3. 只留一帧静态成品、停掉 rAF。

`GeometryBG.state.perf` 里能看到 `{ tier, level, avgFrame }`。实测（无头 Edge）：
桌面 `high`，1440×900 平均帧耗时 **7.8ms**；390×844 安卓 UA + 8 核 → `mid`
（粒子 1657→899、环点 142→72、DPR 1.5→1.25）；再加 2 核 + 2G 内存 → `low`
（粒子 320、环点 28、DPR 1）；开省流 → `budget.background === false`、`window.GeometryBG === undefined`，
页面其余部分照常（已断言 `hero__title` / dock 都在）。

## 小游戏

`views/games.html` + `scripts/games.js` + `styles/games.css`，路由 `#/games`。
现在有三款：**俄罗斯方块**、**Block Blast** 与 **函数球打砖块**。页面本来就是按"多款"搭的：上面是卡片架，下面是机台，
`games.js` 里的 `GAMES` 是唯一事实来源（卡片、dock 搜索、终端 `games` 命令都读它）。

一款游戏 = 一个引擎 + 一个 `.cabinet-group[data-game-group]`。**三块机台都写在页面里，只显示当前这款**
（`Games.mountAll()` 里的 `showGame()` 摘/挂 `hidden`，卡片上的 `is-active` 跟着走）——
换游戏不用重拉页面片段，`i18n-key` 也不会丢。标志位面板就在分组里面，所以
`cab.parentNode.querySelector('[data-game-flags-panel]')` 永远只找到自己那一份，几台机台不会串台。

三个入口走的是同一套挂载逻辑。**点卡片上的 `Play`（或 dock 搜索）只换机台，不自动开局** ——
开局是机台上那颗「开始」的事：这样一来参数（函数球的 f(x)、砖墙、标志位）都还改得动，
不会被"一进来就在跑"锁死。终端 `play` 是例外，它把"直接玩起来"当契约。

| 入口 | 行为 |
| --- | --- |
| dock 的「小游戏」按钮 / 顶栏 `05 Games` / `g` `g` | 进 `#/games`，机台停在 ready，等你按开始 |
| 卡片上的 `Play` | 换成那一款、滚到眼前，**停在 ready**，参数随便改，再按机台上的「开始」 |
| dock 搜索 | 搜 `block` / `blast` 或者中文的"棋盘""三块"都能命中，点一下同样是换成那一款并停在 ready |
| 终端 `play <game> [flags]`（`games` 只列清单） | 挂载完**直接开局**，而且能带标志位（见下）—— 命令行也能开局。唯一例外是函数球：它要先设 f(x)，所以 `play funcball` 也停在 ready（`GAMES[].needsSetup`） |

### 命令行标志位

**每个开关认不认，是"这一款游戏"说了算**（`GAMES[].flags`），而且**只对这一次开局有效**。终端 `play`
按这一份校验：认就开，不认就直接报错并列出这台机台认的开关 —— 不会出现"收下了但什么也没发生"。
（标志位面板是热切换，不用重新挂载；卡片进机台时默认一个都不开。）

| 标志位 | 俄罗斯方块 | Block Blast | 函数球打砖块 |
| --- | --- | --- | --- |
| `--easy-mode` | **不加速**：等级固定 1，下落间隔恒为 800ms（`EASY_GRAVITY_MS`） | **温和出牌**：只出直线与方块（没有拐角），而且长条 / 大方块权重更高，更容易凑满整行整列 | **平坦砖墙**：每层生命值不再乘倍数（那个输入框会被压成 1 并禁掉） |
| `--with-roll-back` | 多一个**撤回**按钮（触屏 ↶、键盘 `U`）：退回上一块落子之前 | 同上，退回**上一次放置**之前，连分数一起还回来 | 不接受（对决是一路向前的，没有可撤回的东西） |
| `--slow-motion` | — | — | 弹跳高度翻倍：每跳更慢，伤害数字看得更清楚 |

```
play tetris --easy-mode --with-roll-back
play blockblast --easy-mode
play funcball --easy-mode --slow-motion
play block-blast          # 别名 block-blast / blast / bb / block_blast 都认
play fball                # 函数球还有 function-ball / functionball / fnball / fb
```

开了标志位的机台，标题栏会挂上小牌子（中文 `不加速` / `可撤回` / `平坦` / `慢放`，英文 `EASY` /
`UNDO` / `FLAT` / `SLOW`），免得忘了自己在什么模式下玩。`games` 会把每款认的开关一起列出来，
`GAMES[].alias` 里的别名 `play` 也认。

**每台机台下面就是它自己的那几个开关**（分组里的 `.flag-panel`）：点一下等价于命令行加参数，
`aria-pressed` / 亮起来的指示灯表示当前状态 —— 不用记命令，也不用回终端。它是**热切换**：
`Games.controller.setFlags()` 直接改 opt，不重挂机台、不重开这一局
（俄罗斯方块的 `--easy-mode` 会立刻把等级拉回 1 并改回恒速；Block Blast 的只影响**接下来补的牌**，
手上那三块不动 —— 已经发出去的牌不可能凭空换掉，这是唯一说得通的做法）。

> **不用的控件一定要收干净。** 俄罗斯方块与 Block Blast 共用 `data-undo-key` / `data-pad="undo"` /
> `[data-*-action="undo"]` 这三处撤回入口，`applyFlags()` 里一并按 `opt.rollback` 摘掉；
> 关掉时连同撤回栈一起清空。实测：打开开关 → 按钮/触屏键/键位图例同时出现、牌子挂上；
> 关掉 → 三者全部 `offsetParent === null`、牌子文字为空、`history === 0`。

> **`hidden` 属性会被作者样式盖掉。** components.css 的 `.btn { display: inline-flex }` 与
> games.css 的 `.cabinet__key { display: inline-flex }` 优先级都高于浏览器默认的
> `[hidden] { display: none }` —— 于是"藏起来"的撤回按钮照样画在屏幕上（只是灰着）。
> 这正是最初的 bug：不开 roll-back 也能看见撤回按钮与 `U 撤回` 图例。
> 现在 games.css 里有一条 `.cabinet [hidden], .flag-panel [hidden] { display: none !important }` 兜底。

> **撤回按钮的可用状态跟着栈走**（`updateUndoBtn()`），不能只在 `sync()` 里刷 ——
> 只在 sync 里刷会晚一步：第一块落地时栈里已经有东西了，按钮却还是灰的，
> 得先按一次 `U` 才会"亮"起来。这是第二个修掉的 bug。

> **撤回撤的是什么。** 每次落子前拍一张快照（板面 / 队列 / 暂存 / 分数 / 正在下的那一块），
> 撤回时把**这一块的软降硬降加分也一起退掉** —— 不然撤了再放一次就是白赚分。
> 栈最多 30 步（`HISTORY_MAX`）；撤到"游戏结束"之前也能接着玩。

> **离开页面就没了。** 标志位与撤回记录只活在这一次挂载里：`route:changed` 一离开 `#/games`
> 就把控制器、`pendingOpts` 与整个撤回栈丢掉，下次进来还是默认机台
> （实测：回去后 `Games.controller.debug()` 的 `easy/rollback` 都是 `false`，撤回按钮重新隐藏）。

### 重新游玩要长按

`Restart` 不是点一下就走：按住 **700ms**（`HOLD_RESTART_MS`）才生效，按住时按钮上一条白色填充
从左扫到右，松手就缩回去。键盘 `R` 同理（按住填满才重开）。指针路径全走 `pointerdown/pointerup`，
`click` 只在 `detail === 0`（键盘触发）时才认，所以不会"点一下 + 长按"重开两次。

> **函数球那台的长按是"回到 ready"，不接着开跑。** 它的参数只在 ready 改得动，所以长按重开必须把
> 编辑权还回来：解锁面板、重画砖墙、计时归零，然后等你按「开始对决」。另外两台没有需要预设置的参数，
> 它们的长按重开就是直接重开一局 —— 那是有意为之（`doRestart()` 各写各的）。

> 长按在触屏上会选中文字 / 弹系统菜单，所以机台里的按钮都加了 `user-select: none` +
> `-webkit-touch-callout: none`，并在 `contextmenu` 上 `preventDefault()`。

### 俄罗斯方块（引擎要点）

- **7-bag 生成**：每七个方块装一袋（袋内七种形状各有且仅有一个，洗牌后依次发），发完再装下一袋。
  跨袋时允许 1/7 的概率与上一袋最后一块同形，所以最多连出两块 —— 连着三块已经不可能。
  `Games.sample(n)` 可以直接看生成序列（调手感 / 跑统计用，不碰正在玩的那局）；`games.js` 顶部的
  `BAG_EDGE_REPEAT = false` 能让它一块都不连着出。

  > **这里踩过一次。** 曾经为了"更随机"改成"每次七选一 + 同一种最多连出三次"。
  > 单看每一块都是均匀的，可连起来经常一边倒。实测 7 万块对比：
  >
  > | | 每次七选一（旧） | 7-bag（现在） |
  > | --- | --- | --- |
  > | 各类型计数（7 万块） | 9955 ~ 10145（差 211） | 每样正好 10000 |
  > | 最长连出 | **3 块**（出现 1238 次） | **2 块** |
  > | 任意连续 7 块里同一种最多几次 | **6 次** | 2 次 |
  > | 固定每 7 块里七种齐全的比例 | 0.5% | 100% |
  >
  > 旧算法随手就能抽到 `I S I Z I / O O O` 这种（"三块同形 + 一块新的 + 三块另一种"），
  > 现在不可能了。另外 `.bag` 也进了撤回快照 —— 撤回之后接下来要出的方块与原时间线一致，不会重掷。
- **旋转 + 踢墙**：`KICKS` 依次试「原地 → 左/右各两格 → 上抬一格」，贴地也转得动；
- **幽灵落点**只描一圈边；**暂存**（`C`）一回合只能用一次；
- 落地有 **400ms 宽限**（`LOCK_MS`），期间挪动会重新计时（最多重置 12 次，防止原地无限转）；
- **消行闪光** 250ms（`CLEAR_MS`）；计分 `100 / 300 / 500 / 800` × 等级，软降 1 分/格、硬降 2 分/格；
- 等级 = 消行数 / 10 + 1，下落间隔 `max(70, 800 × 0.85^(level-1))` ms，最高分写在
  `localStorage` 的 `hayneko.game.tetris.best`。

操作：`←` `→` 移动、`↑` / `X` / `Z` 旋转、`↓` 软降、`Space` 硬降、`C` 暂存、`P` / `Esc` 暂停。
屏幕下面还有一排按钮，触屏也能玩。

长按连发是引擎自己排的（浏览器自带的方向键重复节奏对不上），手感参数就这四个，在 `games.js` 顶部：

```js
var DAS_MS = 250;      // 按住多久才开始连发
var ARR_MS = 75;       // 连发的间隔
var SOFT_DAS_MS = 250; // 软降起步
var SOFT_ARR_MS = 50;  // 软降连发（往下滑过头不心疼）
```

> **这几个值别往回缩。** 一开始写的是 170 / 55，按住一秒能横移 **17 格** ——
> 想挪一两格时手一抖就滑到墙上。现在按标称值算一秒走 **11 格**左右，
> 无头 Edge 里采样实测：起步 `229ms`、连发间隔 `81ms`（rAF 采样有约 16ms 量化）。
> 松手也不会补跳：120ms 的点按只走 **1 格**。
> 浏览器长按时每 30ms 左右会补发一次 `keydown`，这些重复事件由 `held` 挡掉
> （实测连发 36 次 `keydown` 也只按上面的节奏走）。

> **画布尺寸量的是 `clientWidth`，不是 `getBoundingClientRect()`。**
> 入场动画会给 `.page` 挂 `transform`，量矩形拿到的是缩放后的尺寸，
> 画布就会按错的宽度建，画面发糊 —— 而且不会自愈，要等下一次 resize。

> **离开页面要收干净。** `route:changed` 里销毁控制器（摘掉 keydown / ResizeObserver /
> 监听器并停掉 rAF），主循环里还有一道 `canvas.isConnected` 兜底；
> 切走标签页（`visibilitychange`）自动暂停。不然旧机台会在后台一直空转。

> **机台正在跑时，`g` 前缀快捷键不抢按键**（`app.js` 里一问 `Games.active()` 就退出），
> 否则玩着玩着按到 `g` `h` 就跳页了。

### Block Blast

8×8 棋盘，一次三块；把方块放进棋盘，**填满整行或整列就消掉**。没有重力、没有倒计时 ——
手上还有牌、但每一块都放不下时才结束。

- **形状库 21 种**（`BB_SHAPES`）：直线 1~5 连（横竖）、1×1、2×2、3×3、**2×3 与 3×2 矩形**，
  以及 2×2 / 3×3 的"两条边"拐角各 4 个。没有 T / S / Z 这类斜角 —— 原版就没有，有的话棋盘两下就堵死；
- **出牌按权重**（`BB_WEIGHTS`）：五连、"3×3"、大拐角这种大块少出，小块多出。
  权重是"池子里放几份"，抽的时候按份等概率，所以权重就是出现比例；
- **`--easy-mode` 另有自己的权重**（`BB_EASY_WEIGHTS`）：牌池只留直线与方块（13 种，不出拐角），
  权重明显压在长条与大方块上。同一套抽样口径实测 750 块：

  | | 长条（3~5 连） | 方块 + 2×3/3×2 |
  | --- | --- | --- |
  | 普通 | 27.5% | 17.2% |
  | `--easy-mode` | **61.5%** | **28.7%**（两者合计 90%） |

  所以 easy 不只是"少出难放的形状"，而是**更容易凑满整行整列、连击更好拿**；
- **颜色每块随机**（`BB_COLORS` 7 色），同一种形状的每块颜色都不一样；
- **计分**：放下一格 **2 分**（`BB_POINT_PER_CELL`）；一次消掉 n 条（行 + 列一起数）得
  **10·n·(n+1)/2 × 连击倍率** —— 1 条 10 分、2 条 30 分、3 条 60 分。
  `game.combo` 是**这一轮累计消掉多少条线**：消 1 条 +1，一次消 3 条就 **+3**（不是只算一次），
  得分乘的就是加完之后的这个数。没有连击时 HUD 显示 **×0**（不是 ×1）；
- **连击宽限**（`BB_COMBO_GRACE` = 4）：消完之后还能白放 **3** 次，第 4 次再没消掉才清空连击
  （`game.misses` 记账，任何一次消除都把它清零）。所以"断"之前有 4 次机会；
- **连击颜色**（五档）：HUD 上那格的颜色表示这一轮连击的健康度 ——
  **灰**（没连击 / 已中断）→ **白**（刚触发）→ **绿**（空放 1 次）→ **黄**（2 次）→ **红**（3 次，再空放就断）。
  类名 `is-off` / `is-live` / `is-miss1` / `is-miss2` / `is-miss3`；
  **页面下方还有一份 `.combo-legend` 图例**（在 Block Blast 那台的最下面，跟着机台切换显隐），
  色点与 HUD 共用同一套类名 —— 色值只有一份定义，图例不会和实际配色各写各的。
  不这样提示的话，玩家只会觉得"连击莫名其妙没了"；
- **消线有 240ms 闪光**（`BB_CLEAR_MS`），期间不接输入，与俄罗斯方块的消行节奏一致；
- **落点预览（消除提示）**：手里这块放在当前落点，**放下之后会满的行 / 列整条高亮**
  （白色半透明铺满整条 + 亮边描一圈），画在幽灵之上。于是"看到高亮 = 松手就是一次消除"，
  也就意味着这一手会吃到 combo。判据是**虚拟放上去之后这一行/列正好填满**（`previewClears()`，
  用一张一维标记表避免复制板面），不是"只差一格"；挪一格高亮就跟着变，
  没选块 / 落点放不下 / 正在消线时都没有高亮；
- 判负用 `bbFitsAnywhere()`：手上有牌但**每一块都放不下**才 `gameOver()`；
  手牌用完立刻补三块再判一次。最高分记在 `localStorage` 的 `hayneko.game.blockblast.best`。

渲染是**一张 canvas 画完整台**：上面 8×8 棋盘、下面一条 2.6 格高的手牌条
（`BB_TRAY_H`）。这样拖动完全不跨元素，指针坐标只换算一次；井的 `aspect-ratio` 必须是 `8 / 10.6`，
跟画布里的比例一致，否则会留出空白边。棋盘外框用比网格略重的 `gridEdgeColor()` 描一圈 ——
少了这一圈，手牌条看着像第 9、10 行。

> **手牌里的小格子是自适应缩放的。** `slotOrigin()` 取三者最小：常规倍率 `BB_TRAY_SCALE`(0.6)、
> 按格宽能塞下、按格高能塞下。一格只有 8/3 格宽，而五连横过来有 **5 格宽** ——
> 固定 0.6 的话（5 × 0.6 = 3 格）会凸到隔壁格外面去，看起来像多出来一块。
> 现在五连按 `8/3 × 0.84 / 5 ≈ 0.45` 倍画，实测手牌条里每一格的亮像素都落在自己的列范围内。

输入三条路，最后都落到同一组 `game.sel` / `game.cur`（选中的是哪一块 + 落点在哪个格）：

| 输入 | 做法 |
| --- | --- |
| 鼠标 / 手指 | 从手牌条拖到棋盘（松手判定），或者**点一下手牌选中、再点棋盘放下**；移动不到 9px 算"点选"（`BB_DRAG_SLOP`） |
| 键盘 | `1` `2` `3` 选块、方向键移落点、`Space` 放下、`U` 撤回、`P` / `Esc` 暂停、长按 `R` 重开 |
| 触屏键 | 左下十字键移落点，右手两个大键 = 放下 / 换一块（`data-pad="drop"` / `"hold"`） |

落点提示（`drawGhost()`）三种输入共用：放得下就按方块本色描一圈 + 半透明填充，放不下整块变红。
拖动时方块跟着指针走，松手才判定 —— **放不下就退回手牌，方块不会消失**。

> **拖动中的方块会被夹在画布内。** 指针捕获之后 `pointermove` 能跑到画布外面很远，
> 不夹的话方块就被拖出显示区域了（只剩半块、甚至整块看不见）。`dragPos()` 把绘制位置夹在
> `[0, canvas.width - w] × [0, canvas.height - h]` 里，**落点也按夹过的位置算** ——
> 于是"方块画在哪"和"会落在哪"永远一致，不会出现手指已经在画布外、落点还在几十格外跟着跑。
> 另外按下时的抓点也夹在方块自身范围内：小方块在大格子里按到边角，不会一拎起来就偏半格。

> **Block Blast 的主循环是按需唤起的，不常转。** 它没有重力，平时根本不需要逐帧画 ——
> 需要连续排帧的只有消线闪光那 240ms。于是 `requestDraw()` 只把 `dirty` 打开并借一帧 rAF：
> 画完自己把 `raf` 归零停住，页面能真闲着。落点预览是"跟着幽灵走"的**静态**高亮（没有动画），
> 所以它不占主循环。这一条改过一次：最早做成"只差一格的行列一直闪"，那样只要板上有提示，
> 主循环就得一直排帧；改成落点预览之后又回到了纯按需唤起。
> 俄罗斯方块那台则相反，只要在跑就必须一直排帧（下落、锁定宽限、长按连发全在 tick 里）。
>
> `debug()` 里会先算一遍 `previewClears()` 再返回 —— 预览只在 `draw()` 里算的话，
> 快照会比当前落点慢一帧，"此刻按下会消什么"就查不准了（这一条是自动化验证时发现的）。

> **Best 永远不会比 Score 小。** 一开始只在"消线 / 游戏结束"时才更新 `game.best`，
> 于是刚刷新纪录的那一刻 HUD 上会看到 Best 234 / Score 240 这种自相矛盾的数。
> 现在 `updateHud()` 里先把 `best` 抬到不低于当前分（内存里的"运行中最高分"），
> **写盘时机不变**（消线 / 结束时才 `writeBest`）—— 俄罗斯方块那台也一起改了。

### 函数球打砖块

两位选手各一颗函数球，中间一道挡板，各自面对**完全相同**的一堵砖墙。点「开始对决」后两颗球同时下落：

- **球只上下弹，每次弹起的高度恒定**（滑杆 20~140px，`--slow-motion` 再翻倍）。反弹速度直接由
  `v = sqrt(2·g·h)` 反推（`FB_GRAVITY = 1800`），所以不管重力取多少，弹起高度永远正好是 `h` ——
  想让"每跳更慢、看得清数字"就调高度，而不是调重力；
- **每弹一次算一次命中**：这一次的伤害是 `f(x)`，然后 `x` 按「每跳 x 增加」往上涨（默认 +1）。
  于是阶乘球第一下是 `0! = 1`，接着 `1! = 1`、`2! = 2`、`3! = 6`…… 与页面上的说明一致；
- **砖块要掉到 0 以下才碎**（正好打到 0 还留着，得再来一下），**溢出伤害不结转**给下一块。
  一层清空后球落到下一层继续弹；先打穿整堵墙、落到地面的那方获胜，**谁先落地对决立刻结束**（另一方的进度原地冻结）；
- 伤害取整（`Math.round`）：生命值、总伤害、砖块上的大数字因此永远是整数（`10 * 1.35^x` 会算出小数，
  不取整的话 1e9 那格会变成 `957627045.18` 这种没法一眼读的数）。

`f(x)` 由 `games.js` 里的解析器自己算，**不用 `eval` / `new Function`**：支持 `+ - * / % ^`、括号、
后缀阶乘 `!`、一元负号、隐含乘号（`2x` / `3(x+1)` / `2pi`）与科学计数法（`1e6`），函数有
`abs sqrt floor ceil round trunc sign exp log ln log10 log2 sin cos tan pow min max mod gcd fact fib`，
常量 `pi` `e`，变量 `x`（`n` 等价）。页面上五个模板（阶乘 / 百分比变化 / 幂函数 / 斐波那契 / 自定义）
只是往输入框里填一条示例 —— **表达式才是唯一输入**：手动改一个字就自动跳到「自定义」，
球上那个牌子（`n!` / `%` / `xⁿ` / `Fₙ`）跟着表达式走。解析失败时那一栏下面直接写解析器原话（英文），
并且「开始对决」按不下去（`Games.funcball.check("x++")` 也能单独问）。

每层生命值 = `生命值 × 倍数^层号`（上限 1e30）。开跑后整块面板锁住，免得两边看的不是同一堵墙。

> **这台从不自动开局。** 卡片 `Play`、dock 搜索、连终端 `play funcball` 都只把机台换过来停在
> ready —— 一旦开跑，上面那整块参数面板就锁上了，自动开局等于"想调参数的人永远调不到"。
> 想直接玩就按「开始对决」或空格。
>
> **开跑之后也回得去 ready，有三条路。** ① 任何状态（跑着的时候也行）长按「重开」；
> ② **结算之后参数不再锁** —— 改完按「开始对决」就是带着新参数的新一局；③ 结算之后同样可以长按
> 「重开」回到设置。暂停时的提示里写着「想改参数就长按「重开」回到设置」，结算面板底下也写了下一步
> 该按哪个键 —— 这一条是用户反馈后补的：原来结算状态忘了解锁，加上"重开直接就开跑"，就变成了
> 开跑之后再也改不了 f(x) 的死路。
每层生命值 = `生命值 × 倍数^层号`（上限 1e30）。开跑后整块面板锁住，免得两边看的不是同一堵墙。

| 默认 | 值 |
| --- | --- |
| A 方 | `x!`，初始 x = 0，每跳 +1 |
| B 方 | `10 * 1.35^x`，初始 x = 46，每跳 +1 |
| 砖墙 | 3 层 × 1 块，生命值 1000 / 1e6 / 1e9（倍数 1000） |
| 弹跳高度 | 56px（一跳 `2·sqrt(2h/g)` = 0.499s，约 2 次命中/秒） |

这套默认值不是随手填的：**先打穿三层、落到地面**在默认参数下是一场毫厘之争。
`Games.funcball.simulate()` 可以无渲染推演一局，下面是浏览器里实测的那一局：

| | 命中次数 | 总伤害 | 落地用时 |
| --- | --- | --- | --- |
| B 方 `10 * 1.35^x`（胜） | 13 | 1 370 109 714 | **7.26s** |
| A 方 `x!` | 14（整堵墙已经打穿，球还在下落） | 6 749 977 114 | — |

也就是说 A 方**其实已经把三层全打穿了**，只是 B 方早半个来回落地 —— 这就是"谁先落地谁赢"那条规则
在默认参数下的样子（`simulate()` 推演同一组是 7.27s，差一帧）。把 B 的初始 x 调到 47 以上就变成一边倒
（x0 = 52 时 B 只用 7 跳），调到 45 以下则 A 反超成 7.77s。**每一方各自的初始 x 才是这套玩法真正的
平衡旋钮** —— 函数决定曲线形状，起点决定两条曲线什么时候相交。

场上那一行 `x = 46`、每栏的 `5 hits`、砖块上的大数字、命中时上浮的伤害数字都在画布里；
HUD 侧栏只放「用时 / 双方总伤害 / 剩余砖块」。侧栏窄，总伤害超过 11 个字符时按 3 位有效数字
缩成 `5.37e19`（结算面板与 `debug()` 里给的仍是精确值）。

> **页面下方那块说明与 Block Blast 的连击图例共用一套外观。** `.fb-legend` 与 `.combo-legend` 的
> 排版规则是并列选择器（边距 / 字号 / 圆点只有一份定义），各自整块在自己的 `.cabinet-group` 里，
> 换机台时跟着一起显隐。
>
> **`--easy-mode` 在这台的含义是"平坦砖墙"**：每层生命值不再乘倍数。它不是偷偷把数值改小，
> 而是把「每层生命值倍数」那个输入框直接压成 1 并禁掉 —— 开着开关却看到一个没生效的输入框是最糟的。
> `--slow-motion` 只翻倍弹跳高度，滑杆读数同时写成 `56 ×2 = 112`。
> 这两个开关之外的东西这台机台一个都不认：终端 `play` 按 `GAMES[].flags` 校验，
> `play funcball --with-roll-back` 会直接报错并列出这台认的两个开关（实测过：标志位牌子挂在标题栏，
> 关掉后牌子、`is-on`、`aria-pressed` 一起收干净，生命周期与另外两台一致）。
>
> **生命值 / 倍数是两个旋钮。** 倍数调到 1e6 这种量级就是参考图那种"1000 万 → 1e13 → 1e18"的陡墙，
> 那时候只有阶乘、幂函数这类跑得比指数还快的函数打得动 —— 百分比球 `1.35^x` 会被卡在第一层，
> 这本身就是这个游戏想给人看的东西。

> **改参数必须连"场地几何"一起重算。** 砖块高度、每层顶边、砖宽都是按「层数 / 每层砖块数 /
> 弹跳高度」算出来的（`fbGeometry`）—— 只重建 world 而不重算 geo 的话，`geo.rowTop` 还是旧层数：
> 多出来的那几层画不出来（循环被 `rowTop.length` 截断），球撞上 `undefined` 的顶面又永远不落地，
> 会一路掉出画布。这正是用户报的"打完看得见的砖就飞出去了"。现在 `preview()` / `reset()` / `start()`
> / `resize()` 四路都走 `refreshGeo()`；`fbSurfaceY()` 另留一道兜底：顶面读不到就当地面 ——
> 宁可这局打不成，也不能让球掉进虚空。
>
> **球是一列一列打着走的。** 同一层有多块砖时，球先打在还没碎的最左边那块上（横坐标朝它平滑靠过去），
> 打碎一层里的最后一块之后**保持自己的列**直着落到下一层 —— 不是滑回场地中心（那看起来像穿模）。
> `debug().geo` 会把整份几何给出来，验证"改了层数场地有没有跟着变"直接比一下就行。
### 移动端

手机上不用竖着堆（那样要滑很久才够得着按钮，手指还得在两个屏幕高度之间来回跑），
≤720px 直接换成**横向**布局：**井在左**，`Next/Hold`、数据、开始/暂停/撤回/重开在右，手指区在最下面。

| 区域 | 摆法 |
| --- | --- |
| 井 | 左；高度 `clamp(240px, 86vw, 330px)`，宽度按 1:2 反推（390px 实测 165×330，比竖排矮了约 90px） |
| 侧栏 | 右；`grid-template-columns: auto minmax(0, 260px)` + `justify-content: space-between`，井贴左、侧栏贴右 |
| 手指区 | 底部；左边十字键，右边两个大键 |

十字键与右手键：

| 位置 | 键 | 作用 |
| --- | --- | --- |
| 十字键 · 上 | ⟳ | 旋转 |
| 十字键 · 左 / 右 | ← / → | 左右横移 |
| 十字键 · 下 | ↓ | 软降 |
| 右手 · 左 | ⤓ | 硬降 |
| 右手 · 右 | H | 暂存 |
| 右手 · 下（仅 `--with-roll-back`） | ↶ | 撤回，横跨两列 |

摆位用的是 `grid-template-areas`（`. 表示空位`），桌面端（>720px）不受影响，仍是原来那一排小按钮。

- 动作按钮带 `.btn--block`（`width: 100%`），横向排布里会各占一行 —— 手机上排成 **2×2**；
- `.cabinet__pad` 设 `touch-action: none`，按住方向键时手指滑动不会带着页面滚；
- 触屏设备（`@media (hover: none) and (pointer: coarse)`）隐藏键位说明，并去掉 hover 位移
  —— 触摸屏的 `:hover` 会"粘"在最后点过的按钮上；
- 标志位面板在手机上每个开关占满一行（390px 实测 325×74）；
- 实测 390px：机台总高 **591px**（竖排时 ~700+），滚到机台后手指区底部 598px 仍在固定坞顶部 774px 之上，不会被 Dock 压住；
- 320 / 360 / 390 / 430 / 600px 逐档实测均无横向溢出。

**Block Blast 也是"左棋盘 + 右一列"，但井是近方形的**，所以按宽度定尺寸
（`.cabinet--bb .cabinet__well { width: min(60vw, 280px); aspect-ratio: 8 / 10.6 }`），
右侧那一列窄（`minmax(0, 124px)`），按钮改成一列全宽。手指区沿用同一套 `grid-template-areas`，
只是把 `rotate` 那一格换成 `up`（`.cabinet--bb .cabinet__pad [data-pad="up"] { grid-area: up }`）。

实测 390×844（`deviceScaleFactor: 2`、模拟触摸）：

| 量 | 值 |
| --- | --- |
| 棋盘井 | 234×310（含 2.6 格手牌条），**29.3px 一格** |
| 十字键 | 53×53，贴左 |
| 右手两个大键 | 53×**111**，贴右 |
| 整台机台 | 高 **558px**（标题栏 36 + 屏幕 338 + 手指区 182）；dock 高 58px —— 558 + 58 = 616 < 844，滚到机台就是完整一屏 |
| 手指区底边 | 滚到机台后两个大键底边仍在坞顶之上（实测 628 / 774，绝对值随滚动位置变，看的是这个关系） |

> 这里以前记的是 **693px** —— 那是没开触摸模拟时量的：`@media (hover: none) and (pointer: coarse)`
> 没生效，键位说明那张表还占着约 135px。CDP 里要 `Emulation.setTouchEmulationEnabled({ enabled: true })`
> 量出来才是手机上的真实高度（同时"隐藏键位说明"那条检查才有意义）。
>
> 手机上右侧栏只有 87px 宽（390 - 31×2 - 234 - 8），所以数据用 `.hud-stats` 的两列网格

## Arch32S 虚拟机（`#/labs-vm`）

把 `HaynekoArch32VM_python/` 里的模拟器搬进了网页：`scripts/hayneko-arch32.js` 是
`vm.py` + `as.py` 的逐条移植（ISA 仍从 `hayneko_arch32S-v1.json` 读，不抄一份指令表），
`scripts/labs-vm.js` 是仿 `dbg.py` 的调试界面，`styles/labs-vm.css` 负责排版。

布局与 dbg.py 一致：顶部工具栏（F7 单步 / F8 跳过调用 / Ctrl+F8 跳出 / F9 运行），
左边反汇编窗口（当前指令高亮，单击一行切断点），右边寄存器 + 栈 + 内存转储，
底部输出（端口 `0x00` / `0x01` 的写入）；下面还有终端和命令速查。

排版上几个刻意的决定：

- **当前运行指令独占 VM 栏的第一行**：指令靠左、机器状态贴右（放工具栏里长指令会把
  按钮挤到换行；挤在状态旁边又会被省略号截掉）。独占一行后 40 多个字符也放得下。
- **自动运行（取代原来的无限速 F9）**：▶ 按钮 / F9 按数字框里的速率跑，
  速率 = 每秒指令数，范围 1..100000（100 kHz），跑的时候改数字立刻生效；
  **单次运行不再有指令上限** —— 想停就暂停（或再按一次 F9），每帧只占 12ms 时间片，
  所以页面不会卡死。终端里 `vm <name> run`（不带条数）走同一套调度器，
  `vm <name> run 500` 仍然同步跑指定条数。
- **反汇编是一段"从 0x0 开始的程序"，不是跟着 ip 走的 81 行小窗口**：窗口默认覆盖
  512 字节（ip 跑远会自动加长，而 `from` 永远是 0），所以任何指令 / 寄存器变动都不会
  把 0x00000000 那段挤掉、滚轮还能滚回去。窗口内内存算了个廉价校验和，内容一变
  （命令行写指令、换示例、自修改代码）就重新解码渲染 —— 是实时的；只移动高亮时不重建 DOM。
- **输出面板放在反汇编下面**：左列 = 快捷输入 + 反汇编 + 输出，右列 = 寄存器 / 栈 / 内存，
  两列底边对齐（输出底边与内存转储齐平）—— 之前反汇编下面会空出一大块，现在那块是输出。
- **高度由 JS 算**（`fitHeight()`）：面板区给一个「窗口高 − 网格顶部 − 底部固定坞」的
  `min-height`（是 min-height 不是 height —— 面板不够高时就让整页滚动，别把面板压扁），
  反汇编吸走左列剩下的空间后再收紧到 `行高 19px × 整数行`，所以它尽量铺满、
  不被坞压住、底部也不会露出半行。反汇编最少 30 行，栈最少 280px，内存转储最少 300px；
  实测 1600×1000 下是反汇编 37 行 / 栈 13 行 / 内存 14 行。
- **字节列必须写死宽度**（`45ch` = 15 字节 = 最长指令）：每行是各自的 grid，
  用 `max-content` 会让"十六进制 | 指令"逐行错位、贴在一起；列间留 16px。
- 配合 `scroll-snap-type: y mandatory`：滚动位置永远落在行边界上，
  底部不会露出被切掉一半的指令。
- **本页不做移动端适配**：容器放宽到 1880px（`[data-route-current="labs-vm"] .page.wrap`），
  窄窗口直接横向滚动，保证每一列的宽度；移动端布局交给别的页面。
- 内存转储每行 16 字节（256B/屏），栈窗口 26 行。
- **256×256 小型显示屏**（右列第一块）：总线是 `OUT` 逐字节送，端口各自按**大端**收满
  4 个字节拼成一个字 —— `0x04 MNTRCONTROL` = `[x, y, 空, 空]`（第 1 字节 x、第 0 字节 y），
  `0x05 MNTRCOLOR` = `[R, G, B, refresh]`（refresh `0x00` 只存缓冲区、`0xFF` 立即刷新、
  其余丢弃）。面板上有 screen/buffer 切换、清屏、光标坐标与帧数。三个现成的例子：
  `demo screen`（缓冲区里画 32×32 渐变点阵，最后刷新一次）、
  `demo helloworld`（**5×7 点阵**方块字，第一行 HELLO、第二行 WORLD，55785 条指令 / 2448 帧）、
  `demo syscall-font`（**SYSCALL 调字体绘制库**：程序登记 idt[0x40] 后按 ABI 传参，
  库把 A-Z + 空格的 5×7 字形画上屏，75307 条指令 / 2820 帧）以及它的
  `demo syscall-font-opt`（同一程序按「最短编码」重写：IMM→IMMB、ADDIDW→ADDIB、
  躲开高位寄存器的 REX 前缀字节、循环改倒计数，**723B → 650B**、75307 → 65732 条指令，
  屏幕逐字节一致）。速率拉到 100000 ips 都是秒级画完。
  示例的字体格式、显示屏总线、系统调用约定都写在 `asmdemo/README.md`。
- **ISA 体检程序** `demo isa-coverage`（`asmdemo/isa-coverage.asm`）：一份程序里塞进 ISA 的
  **全部 156 条指令**、全部 31 个可写通用寄存器（x0 是硬件零寄存器）、内存读写、显示屏与控制台
  端口、中断（INT/BRK → IRET）与系统调用（SYSCALL → SYSRET），用来同时体检**汇编器**
  （每条都能编码）、**反汇编器**（把反汇编文本再汇编回去，239/239 条字节一致）和**执行引擎**
  （**顺序已打乱**、并保证每条都真的被执行到：240/240 条指令起始地址都被跑到，257 步到 HALT，
  两个实现除 RANDOM 写的那个寄存器外逐字节一致：878B ROM、内存/屏幕哈希、执行过的地址集合全同；
  IDT 里给 #DIV/#NMI/#HLT/#MAV/#UDI/#PGF 都挂了兜底处理程序，任何意外异常都只会收尾、不会再跳回 0 死循环）。
  快捷输入框里还可以敲 `# <一条指令>` 直接执行一条指令（不写内存/ROM、不推进 ip）。
- **反汇编上面有一条快捷命令输入**（`vm$` 那一行，Enter 执行、↑↓ 翻历史），敲完在原地
  回显最后一行；下面那块终端照旧保留，两边走的是同一份命令实现。

- **上传**：`.asm/.s/.txt` 当汇编源码（可一键汇编进 ROM），1024 B 当 ROM，256 KB 当磁盘，
  全零/无法判断的按原样收下；也可以把文件直接拖到工作台上。ROM / 磁盘都能导出下载。
- **终端命令**：`vm new vm1 --demo=fib`、`vm vm1 inst nop`（汇编并执行一条指令）、
  `vm vm1 step|run [n]`、`vm vm1 regs|mem|dis|info`、`vm vm1 bp <addr>|clear`、
  `vm vm1 demo <id>`（示例源码都在仓库根的 `asmdemo/`，
  网页版 fetch 同一批文件）、`vm vm1 rom|disk|save …`。

  也能建机器（只是看不到面板）；页面按钮与命令走的是同一份实现，不会出现两边行为不一致。
- **多台虚拟机**：`vm` 列表里的机器同时存在，VM 下拉框切换；`bp`、`ip`、输出缓冲各自独立。
- **与 vm.py 的差异**：文件系统换成内存里的 `Uint8Array`（磁盘默认 256 KB 全零），
  控制台输出走回调，`RANDOM` 用 `Math.random()`。此前记录过的 `PUSHIMMW`（`FORMAT` 里的
  `IM16` 没登记 → KeyError）已经**在两边都修好**：python 的 `FIELD_SIZES` 补上了 `IM16`，
  长度按 format 推导是 4 字节。
- **NOP 系列是填充指令**（`NOP2`..`NOP15`）：汇编器允许整体省略操作数
  （`vm vm1 inst NOP15` → `80 0F 00…`，缺的字段按 0 编码；写全也一样）；
  反汇编只显示助记符（`80 1F 11 00…` → `NOP15`），页面里这类行带 `.is-pad` 淡化显示
  （但当前指令落在它上面时仍然是近白高亮）。其他指令仍要求操作数个数一致。
- **中断返回地址（已修）**：`INT` / `BRK` / `SYSCALL` 入栈的是**下一条指令**的地址
  （旧版压 `INT` 自己的地址，`IRET` 之后又回到那条 `INT` —— `demo intr` 会死循环；
  现在它会打印 2468 然后 HALT）。异常仍压出错那条指令的地址，处理程序可以修正后重试。
  两边实现（`vm.py` 与 `hayneko-arch32.js`）同步改了，分别用 `_next_ip` / `nextIp`。
- **验证**：拿 5 个内置示例 + 200 个随机 ROM（每条指令的 ip/字节/反汇编/全部寄存器/标志/
  内存哈希/输出）与 python 版逐条对拍，结果完全一致（只有 `RANDOM` 需要固定随机数序列；
  200 个随机 ROM 里有 1 个以 `PUSHIMMW` 开头，正好落在上面提到的 python KeyError 上）。

## 动效

### 入场编排（`Motion.entrance`）

页面注入后，`[data-smear]` 元素分两类处理：

- **在视口里的** —— 立刻按顺序播 smear 入场（`drop` / `slide` / `pop`）；
- **在视口外的** —— 交给 `IntersectionObserver`，**滚动到眼前时才播**。

这一条很关键：以前所有元素都在注入那一刻一起播完，首屏之外的等于白播，
所以页面越长越显得"没有动画"。现在往下滚，内容才会一个个到位。

配套的 `html.fx-ready [data-smear]:not(.is-revealed) { opacity: 0 }` 只在
JS 可用且非降级时生效；另有 8 秒兜底，避免任何元素卡在隐藏状态。

### 其它

- **标题逐字入场**：`[data-fx-split]` 的标题会拆成单字，按 34ms 依次带模糊落下；
  切语言时会重新拆一次，不会重复；

  > **每个字都不该永久带着一层滤镜 / 一个合成层。** 这里原来有两处，
  > 都会让"放大/位移之后文字发虚"：
  >
  > 1. `.fx-char` 上写着常驻的 `will-change: transform, opacity, filter` ——
  >    等于把**每一个标题字**永久提升成一个合成层（层里的纹理按固定比例栅格化，
  >    缩放时就是糊的），而且 `filter` 的模糊动画本来也交不给合成器做，
  >    这条 `will-change` 什么也换不来。现在整条删掉；
  > 2. 动画写的是 `animation: ... both`，于是跑完之后末尾关键帧一直挂着 ——
  >    而只要 `filter` 不是 `none`（哪怕只是 `blur(0px)`），元素就还是个滤镜层。
  >    改成 `backwards`：只保留"延迟期间先别显示"，跑完就把元素交还给 CSS 自身状态
  >    （末尾关键帧和默认状态本来就完全一致，所以收尾不会有跳变）。
  >
  > 实测（首页 + 小游戏页 + 实验室页）：稳定后整页"计算出的 filter 不是 none"的元素
  > 从 **7 个**（全是标题的单字）降到 **0 个**；逐字动画本身没变，
  > 仍是从 `blur(4px)` 一路收敛到 0（采样：`1ms 4px → 40ms 0.46px → 151ms 0.022px`）。
- **标题下划线**：`.section__title` / `.page-head__title` 入场时一道 RGB 细线扫开；
- **卡片跟随高光**：`.card` / `.sim-card` / `.profile-card` 等的高光跟着指针走；
- **按钮扫光**：hover 时一道高光横扫过按钮；
- **悬停放大 / 按下缩小**（统一规则，**不带位移**）：
  `.btn` 1.05 / 0.93，卡片 1.022 / 0.99，`.dock__item` 1.14 / 0.88，
  徽章与终端 chip 1.08，列表行 1.006；曲线用 `--ease-pop` 带一点回弹。
  > **坑 1**：入场用的是 `fill:'both'` 的 WAAPI 动画，跑完后它会一直占着
  > `transform`，CSS 的 `:hover` 根本盖不过去 —— 卡片悬停不放大就是这个原因。
  > 所以 `motion.js` 在动画结束后会立刻 `dispose()` 把控制权还给 CSS。
  >
  > **坑 2**：`.card:hover` 原来会换成另一个 `linear-gradient` 背景。
  > 渐变**不能插值**，所以鼠标一上去底色是"啪"地跳一下。现在卡片悬停不再换背景，
  > 变亮改由 `::after` 叠一层可过渡的 `--tint-hover` 承担。
- **悬停描边（画一圈，再原路退回）**：`.btn` / `.badge` / 终端 chip
  悬停时，一圈 2px 高光**从 12 点方向顺时针逐渐画出来**，移开鼠标后**沿同一条路径退回去**，
  不是一直转圈。做法是把画笔长度注册成可插值的自定义属性：

  > **Dock 图标不再有这圈描边。** `.dock__item::after` 已经从下面那组选择器里摘掉了 ——
  > 坞本身就是"贴着屏幕底边的一排图标"，再加一圈会跑的高光显得吵；
  > 现在坞图标悬停只有底色 + 边框 + 放大三档静态反馈。
  > 想恢复的话，把 `.dock__item` 加回 `motion.css` 里那两处选择器即可。

  ```css
  @property --fx-draw { syntax: '<percentage>'; initial-value: 0%; inherits: false; }
  /* 悬停 → --fx-draw: 100%，靠 transition 在 680ms 内插值 */
  ```

  实测（每帧读 `--fx-draw`）：画 `39ms:0.1% → 139ms:9.1% → 305ms:64.6% → 522ms:95.4%`，
  退回 `605ms:97.6% → 706ms:88.3% → 823ms:48.6% → 1055ms:5.9%`。
  不支持 `@property` 时降级为"直接出现一整圈"；
- **入场的运动模糊（零副本）**：入场**不生成克隆残影**（`ghosts: 0`），
  而是把 `filter: blur()` 直接写进关键帧，模糊量跟着速度走 ——
  `dropIn` 从 `blur(9px)` 收到 `blur(0)`，`slideIn` 从 `5.5px`，`popIn` 从 `4.5px`。
  实测入场全程 `#smear-host` 子节点数 = **0**，元素自身 `blur(5.5px) → 2.27px → 0.21px → none`。

  > **为什么入场不能用克隆残影。** 克隆残影本质就是"同一份内容的另一个 DOM 节点"。
  > 把残影和**它自己的**主体对比实测：最近的那层也会从 0 拉到 **22px** ——
  > 屏幕上就是"复制了一份元素 / 有虚影"。调 `lag` / `blur` / `opacity` 只能减轻，治不了根：
  > 只要它和主体拉开几像素，人眼就读成两份，而不是糊。
  >
  > 克隆拖影现在只留给**顶栏菜单**（一瞬间的残影，不会读成"复制"）。

- **位移时的运动模糊**：任何涉及 `transform` / `padding-left` / `top` / `left` 的过渡一开始，
  `motion.js` 就给元素挂上 `.is-moving`，**这些属性全部跑完**才摘掉。
  模糊量不是定值，而是**每帧按元素真实的位移速度算**（`模糊 = 速度 × 3.2`，上限由
  `--fx-move-max` 给：图标 0.45px / 卡片 0.8px）。悬停放大、按下缩小、列表行缩进因此都带上拖影感，
  但位移一停下来模糊立刻回到 0；

  > **模糊必须和动画同长 —— 长一头短一头都看得出来，这里两头都修过。**
  >
  > 1. **模糊比动画长（入场）。** 入场动画用 `fill: 'both'` 挂着 `filter`，而释放写的是
  >    `setTimeout(total + 90)`。动画其实早就跑完了（关键帧最后一帧就是 `blur(0)`），
  >    但只要动画还挂着，元素就一直是**带滤镜的合成层**：真机上先栅格化成纹理再缩放，
  >    于是"动画结束后还糊一小会"。实测那段尾巴：动画 `766ms` 结束、`filter` 拖到 `878ms` 才变 `none`
  >    （**多挂 110ms**）。现在直接在动画自己的 `finished` 上释放（兜底计时器才 +120ms），
  >    实测 `filter: none` 与"动画消失"同一时刻（`785ms == 785ms`）。
  > 2. **模糊比动画短（多属性过渡）。** `.file-row` 是"缩放 `transform 240ms` + 左移 `padding-left 420ms`"，
  >    而摘模糊写的是"谁先 `transitionend` 就摘" —— 实测 `397ms` 就变清晰，位移却一直到 `591ms` 才停
  >    （**早了 194ms**，那段位移是"没有拖影感的裸平移"）。现在按属性各自计数，
  >    全部结束才摘；顺带忽略**伪元素**的过渡（按钮扫光 `::after`、卡片高光 `::before`
  >    只是装饰性扫过，不该把模糊拖长）。实测改成 `514ms` 摘、位移 `566ms` 停，
  >    差的 52ms 正好是 rAF 采样间隔的量级。
  > 3. **模糊不该比"位移量"还大（会糊到文字）。** 原来 `.is-moving` 是三个定值
  >    （0.45 / 0.7 / 0.9px），只要一悬停就糊满整段过渡 —— 可卡片只放大 **2.2%**，
  >    坞图标是 **14%**，两者用同一个量级本来就说不通：小位移元素的文字先糊了，
  >    看着就像"字突然变虚"，而不是"元素在动"。
  >    现在模糊跟着**每帧实测到的位移速度**走（`模糊 = 速度(px/ms) × 3.2`，再按元素的
  >    `--fx-move-max` 封顶），停下来自然回到 0。实测卡片悬停：峰值 **0.37px**（原先恒定 0.9px），
  >    约 290ms 后回到 0，之后整段悬停状态文字都是清晰的；坞图标因为又快又大，
  >    峰值仍有 **0.42px**，拖影感没丢。
  >    慢于 `0.02px/ms` 直接当没动（免得挂一层噪声级的模糊）。
  >
  > **剩下的那点"放大后有点软"，是合成器的事，不是这里的模糊。** 元素一旦被提升成
  > 合成层，它的纹理是按某个固定比例栅格化的，动画期间由 GPU 缩放这张纹理 ——
  > 那一下字会略软，Chrome 在过渡结束后会按最终比例重新栅格化。
  > 无头（软件光栅化）测不出来，所以这条只能靠上面"把模糊降到 0"来尽量减少叠加效应。
- **当前页面高亮**：坞里当前页面对应的图标会变成强调色（`.dock__item.is-active`），
  其余是灰的。原本还有一条"滑动指示条"，已经删掉了 —— 试过三种做法都不理想：

  | 做法 | 问题 |
  | --- | --- |

## 动效偏好（减少动态效果）

系统 / 浏览器开了「减少动态效果」时，`scripts/motion-pref.js` 会给 `<html>` 挂上
`reduce-motion` 与 `data-motion`，CSS 与各动效模块（smear / geometry-bg / motion）都读它。

> **踩过一个很深的坑，记在这里。** 原先写的是
>
> ```css
> @media (prefers-reduced-motion: reduce) {
>   *, *::before, *::after {
>     transition-duration: 0.001ms !important;
>     animation-duration: 0.001ms !important;
>     animation-iteration-count: 1 !important;
>   }
> }
> ```
>
> 这条规则把**所有**过渡和循环动画一刀切了。实测（headless 里模拟 reduce）：
> `btn transition-duration` 变成 `1e-06s`，描边高光的 `animation-name` 变成 `none`。
> 于是悬停放大是"啪"地跳、描边高光定在原地不动 —— 看起来完全像"没有动画"。
> 开着「减少动态效果」的人看到的正是这个样子。

现在只关掉真正可能引起不适的**大幅 / 长时间**动效：

| 保留 | 关闭 |
| --- | --- |
| 悬停放大、按下缩小 | 页面切换的整屏位移 + 模糊 |
| 颜色 / 边框 / 阴影过渡 | 入场 smear 拖影、逐字标题 |
| 描边高光绕圈 | 主题整屏擦除、路由扫描带 |
| 卡片跟随高光、涟漪 | ASCII 背景的字符游走与 3D 摆动(只画一帧静态成品)、CRT 扫描线、粒子 |

想要全部打开：

```
index.html?motion=full    # 打开全部动效并记住
index.html?motion=reduce  # 强制减弱
index.html?motion=auto    # 恢复跟随系统
```

系统处于 reduce 时首次打开会弹一条提示，里面直接带「开启完整动效」按钮。

### 字体

正文默认 = **英文等宽 + 中日韩衬线**（`tokens.css` 的 `--font`）。

```css
--font-cjk-serif: "Noto Serif CJK SC", "Source Han Serif SC", "Source Han Serif CN",
    "Songti SC", "STSong", "SimSun", "Noto Serif JP", "Yu Mincho", "Hiragino Mincho ProN",
    "Noto Serif KR", "Nanum Myeongjo", "Batang", serif;
--font-latin-mono: "JetBrains Mono", "Cascadia Mono", "SFMono-Regular", "SF Mono", Menlo,
    Consolas, "Liberation Mono", "Courier New", ui-monospace;
--font: var(--font-latin-mono), var(--font-cjk-serif);
```

**不是字体混排，就是字体回退本身**：等宽字体基本不含 CJK 字形，浏览器排到中文时
会自动继续往下找，于是落到后面那串衬线（宋体 / 明朝体）。

> ⚠️ 顺序不能反，拉丁那段也**不能带末尾的泛型 `monospace`** ——
> 泛型会先被解析成一个具体字体，一旦它带 CJK 字形，中文就轮不到后面的衬线了。
> 所以拉丁部分单独拆成 `--font-latin-mono`。

实测（无头 Edge，同一台机器）：

| | 判定方式 | 结果 |
| --- | --- | --- |
| 英文 | 量 `Hayneko 1234` 的宽度 | **281.25 == Cascadia Mono**（Consolas 263.91、Arial 257.97 都对不上） |
| 中文 | 与参考字体并排渲染对比 | 与**泛型 `serif`** 逐像素一致 → 宋体 ✓ |

`code` / `kbd` / `pre` / 终端仍然用 `--font-mono`（连中文也是等宽），因为那里要对齐。

`calc` 是手写的**词法分析 + 递归下降**求值器（**不用 `eval`**）：

| 类别 | 内容 |
| --- | --- |
| 运算 | `+ - * / % ^`（`^` 右结合）、一元 `±`、括号、`0x` 字面量、`pi` / `e` / `true` / `false` |
| 函数 | **原有** `sqrt abs round floor ceil sin cos tan log log10 exp pow min max`；**新增** `sinh cosh tanh asin acos atan asinh acosh atanh cbrt` |
| 位运算（7 种） | `NOT x`、`x AND y`、`x NAND y`、`x OR y`、`x NOR y`、`x XOR y`、`x XNOR y` —— 按 **32 位有符号整数**算，输出十进制结果 |
| 判断 | `=` `<>` `>` `<` `>=` `<=` `~=`（也认 `==` `!=`）→ 输出 **TRUE / FALSE** |

优先级（低 → 高）：`OR/NOR < XOR/XNOR < AND/NAND < NOT < 比较 < + - < * / % < 一元± < ^`。

> **比较运算符和位运算符的输出不是一回事，别记混。**
> 只有比较（`=` `<` `>=` …）在"判断条件是否成立"，输出 `TRUE` / `FALSE`；
> `AND` / `OR` / `XOR` / `NAND` / `NOR` / `XNOR` / `NOT` 是**位运算**，
> 结果是按位算完的 **32 位有符号整数**，照样打印十进制数字：
>
> ```
> calc 1=2          FALSE     比较: 成不成立
> calc 3 xnor 4     -8        位运算: ~(3 ^ 4) = ~7
> calc 12 AND 10    8         1100 & 1010 = 1000
> calc 3 NAND 4     -1        ~(3 & 4) = ~0
> calc NOT 0        -1        ~0
> ```
>
> 布尔值只有在进入位运算 / 算术时才当 1 / 0 用（`calc (1<2) AND 3` 得 `1`，`calc (1<2)+1` 得 `2`）。

几条特意做成这样的：

- **括号没闭合会自动补齐，而且补在哪儿很有讲究。** 括号里若出现**同层的位运算 / 比较运算**，
  右括号补在那个运算符**前面**（把它留在括号外）；没有这类运算符才补在最末尾：

  ```
  calc 1+2*3-sin(1 and 1   →  1+2*3-sin(1) and 1     ← 补在 and 前, 不是 sin(1 and 1)
  calc (1+2*3 and 4        →  (1+2*3) and 4
  calc 1+2*3-sin(1         →  1+2*3-sin(1)            ← 没有这类运算符, 照样补在末尾
  ```

  结果行里显示的就是补完之后的表达式，另有一条灰色 note 说明补了几个；
- **只在真的容易读错时才警告**（结果照给，按上面的次序算）。`3+2*3-4` 这种"先乘除后加减"是常识，
  **不提醒** —— 每次都念一遍等于没念。会提醒的是这四类，而且消息里用的都是**你输入的那条式子**，
  直接给出两种写法与各自的取值：

  | 例子 | 提示 |
  | --- | --- |
  | `1 xor 2 + 3 and 4` | 位运算与算术混在一起 |
  | `2^3^4` | `write 2^(3^4) = 2.417851639229e+24 or (2^3)^4 = 4096` |
  | `-3^3` | `write -(3^3) = -27 or (-3)^3 = -27` |
  | `1 < 2 < 3` | 连着写比较，按 `(1 < 2) < 3` 算 |

  写清括号就都不提醒：`(1+2)*3`、`2^(3^4)`、`(-3)^2`、`5 >= 5 AND 1 <> 2`（后者是两个独立比较）；
- **不支持 `2x` / `2(3)` 这种省略乘号**，报错时直接告诉你该写成 `2 * x`；
- 比较沿用显示的精度（12 位小数）：`calc 0.1+0.2 = 0.3` → **TRUE**，不会出现"显示 0.3 却判 FALSE"。

## 几个容易踩的坑（已修，留个记录）

1. **`data-route` 不要挂到 `<html>` 上。**
   曾经用 `document.documentElement.setAttribute('data-route', id)` 记录当前路由，
   而点击拦截写的是 `e.target.closest('[data-route]')` —— 于是**页面上任何一次点击**
   都会向上找到 `<html>`，被当成站内链接 `preventDefault()` 掉，
   结果 dock 按钮切不动页面、所有外链/下载都点不开。
   现在属性叫 `data-route-current`，拦截器也收紧成 `a[data-route]`。

2. **块注释里的星号加斜杠会提前结束注释，反过来漏写 `*/` 更糟。**
   两者都踩过：一次是注释里写了 cron 表达式，把后面的代码当成注释外的内容（语法错误）；
   一次是删代码时留下一个**没闭合**的 `*` + `/`，于是整个文件后半段的 CSS 全被吞掉 ——
   坞里的图标突然都不见了。现在 `README` 的检查里会比对 `/*` 与 `*/` 的数量。

   > **同一个文件里，特异性相同就完全靠先后顺序决胜。**
   > 这条把"点一下按钮变得超级大"这个 bug 拖了很久。`.fx-ripple`（涟漪）本来写在
   > `.card > * , .btn > * { position: relative; z-index: 1; }` **前面**，
   > 两者特异性都是 0,1,0 —— 于是后者赢，涟漪被设成 `position: relative`。
   > 它的大小是按钮的 2.1 倍，一旦参与布局就把按钮撑到 2.1 倍，点一下"超级大再缩回去"。
   > 实测按钮矩形从 **160×47 直接变成 492×355**。
   >
   > 修法是把涟漪规则挪到 `.btn > *` 之后（`motion.css` 整体又排在 `components.css` 之后，
   > 所以那边同名的 `.btn > *` 也不构成威胁）。实测改完后同样的点击只会经过
   > 悬停 1.05 / 按下 0.94 的正常缩放，最大宽度 168px（= 160 × 1.05）。
   > 现在 `.fx-ripple` 上方留了警示注释，别再往前挪。

3. **`i18n.apply()` 会派发 `i18n:applied`。**
   如果监听 `i18n:applied` 的回调里又调用 `i18n.apply()`，就会无限递归爆栈。
   现在 `renderSearch()` 不再调用 `apply`，并且加了再入保护。

4. **触摸设备上顶栏"点一下展开、立刻又收回"。**
   顶栏那条 `<div role="button" tabindex="0">` 一旦拿到焦点就展开面板；手机上点它的事件顺序是
   `pointerdown → mousedown → focus → click` —— focus 先把面板展开，紧接着**同一个手势**的
   `click` 又 `toggle()` 一次，于是"弹一下马上收回"。第二次点却正常，因为焦点已经在顶栏上，
   不会再触发 focus。无头 Edge 里实测的时间线：

   ```
   245ms  mousedown / focus   active=header-bar  :focus-visible=false  → is-open=true
   259ms  click                                                     → is-open=false
   ```

   当时的修法是 `header-nav.js` 里的 `focusOpens()`：触摸设备（`hover: none`）**只有
   `:focus-visible` 来的焦点**（键盘 Tab）才展开，鼠标/手指点出来的焦点交给 click 去 toggle。

   > **后来顶栏改成"只认点击"（不再 hover 展开），这条 workaround 整个删掉了。**
   > 既然没有"聚焦就展开"，也就不可能再出现"focus 展开 + 同一个手势的 click 收起"。
   > 现在展开只有一条路：点顶栏 / 在顶栏上按 Enter 空格 / `Ctrl`+`K`；
   > 收起有：再点一次、点顶栏外、`Esc`、点完导航项（`route:changed` 里收）、焦点离开顶栏。
   > 实测：鼠标只划过顶栏 `is-open` 保持 `false`；点一下变 `true`，再点回 `false`。
