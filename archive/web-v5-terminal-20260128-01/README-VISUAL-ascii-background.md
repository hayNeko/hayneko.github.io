# 旧版视觉说明 (ASCII 字符网格背景)

## 视觉：三色 + ASCII 背景

主色仍是黑底 + 白字，`--red` / `--green` / `--blue` 三个语义色负责点缀与状态
（深色主题 `#ff4d5a` / `#3ce07b` / `#4d9dff`，浅色主题压深一档），顶栏的「强调色」开关
在三者之间切换（`data-accent`），终端里对应 `accent red|green|blue`。

**背景是一块字符网格**（`scripts/geometry-bg.js`）—— 不是"拿字符当 sprite 的矢量动画"，
而是**离散**的那种：终端里每个字符占一个整数行列，没有浮点坐标，也不能半格移动。
"移动"= 上一帧在 (row, col) 的字符消失、下一帧在 (row+1, col) 出现。
代码里对应两处：

- 绘制前一律 `gx = Math.round(p.x / cell) * cell`（吸附到**字符格**，不是像素）；
- 装配进度也量化成整数步：`Math.floor(k * p.steps) / p.steps`，
  `p.steps = 路径长度 / 格宽`，于是一步跨一格，是跳格而不是平滑滑动。

### 画面构成（自上而下，整体居中）

| 元素 | 说明 |
| --- | --- |
| **3D ASCII 星球 + 行星环** | 球面按纬度分带撒点（`buildPlanet()`），法线与光向点积决定字符与亮度，背面剔除 + 画家算法排序；两圈环在赤道面上（半径 `1.72R / 2.08R`），被球挡住的那半圈会挖掉。**正面朝向鼠标** |
| **`MIKU ICHINOSE`** | 离屏栅格化的等宽字形，居中；字面 + 2 层右下方向的暗影 |
| **当前路径** | 掩码的第二行（`~/home` / `~/labs` …），从 `Router.path()` 读，跟着路由走 |
| 散字 | 满屏游走，装配完成后压暗 |

### 三段式

1. `fill` —— 页面加载后先**铺满一屏字符**（散字按"抖动网格"落位，不是随机撒，免得一块一块），
   开场先来一圈**大涟漪**（起始半径 = 视口短边 × 0.18，扫过时把字符推开一格再亮一下）；
2. `assemble` —— 该去拼字的字符沿**随机曲线**跳着归位。曲线仍是二次贝塞尔
   （控制点在起终点连线的中垂方向随机外扩 16%~40% 屏宽），但**位置逐帧吸附到格点**，
   所以看上去是一串离散的落点，不是一条光滑轨迹；
3. `lock` —— 锁成 3D 字型：字面 + 2 层暗影，每层**整数格**向右、向下各错 1 格
   （`LAYER_DX = LAYER_DY = 1`），就是传统 ASCII 立体字那种右下方向的投影。
   字型静止朝向 `REST_YAW = 0`、`tilt = 0`；每 9s 还有一条扫描带自上而下扫过。

> **文字必须严格轴对齐。** 早先留了 `REST_YAW = 0.26`，字面会被 `cos(yaw)` 横向压掉 3% ——
> 86 列里有若干相邻列被压到同一格，字上就出现一排缺口，看着凹凸不平。
> 现在立体感完全由暗影层的整数格偏移提供，字面一格不差（实测同一掩码行不会落到两行、
> 同一列不会落到两列：`splitRows = 0 / splitCols = 0`）。

### 朝向鼠标：物件正面指着指针

星球（以及打开 `POINTER_FOLLOW` 时的文字）朝向指针，符号是推导出来的：

- `yaw = −pointer.x × 0.62`：鼠标在右边 → 球面**右转**；
- `tilt = +pointer.y × 0.34`：鼠标在上边 → 球面**抬头**。

> 这两个正负号一开始是反的（鼠标往右球面往左、鼠标往上球面低头），
> 因为把"正面法线朝观察者"当成了 `+z`。z 在本文件里是**离观察者越来越远**的方向，
> 所以正面法线是 `−z`：代入旋转矩阵 `(x' = x·cos + z·sin, z' = −x·sin + z·cos)` 得到
> `normal = (−sin yaw, sin tilt, −cos·cos)` —— 想让法线指向鼠标那一侧，就得上面那两个符号。
> 实测：鼠标移到右上角 `yaw = −0.59 / tilt = −0.28`，移到左下角 `yaw = +0.57 / tilt = +0.31`。

> 文字部分即使打开 `POINTER_FOLLOW` 也不吃 `tilt`（保持 0）：字符吸附在格子上，
> 一旦剪切超过半格整行字就会翻行。

### 切路由：文字打乱重排，星球不动

路由换页会派 `route:changed`，`GeometryBG` 收到后：重新栅格化掩码（路径那行变了）→
重建文字目标 → `scrambleText()` 把所有文字粒子扔回满屏随机格、`lock` 清零、重新计时。
星球不在粒子系统里（它每帧按参数现算），所以完全不受影响。

> 这里踩过一个坑：粒子的 `delay` 原本是相对时间轴 0 点算的，换页那一刻 `t` 已经跑了几千毫秒，
> 新粒子第一帧就 `k = 1` 直接到位 —— 打乱动画根本看不见。现在 `delay = relNow() + 随机`。

### 字形是"栅格化"来的

早先试过 5x7 点阵 + 按笔画挑 `|` `-` `/` `\` `+` 画字，好看但只能算"线框图"。
现在换成**真字形**（`rasterizeMask()`）：

1. 在离屏 canvas 上用**浏览器自带的等宽字体**（`ui-monospace` / Menlo / Consolas 那一档）把
   `"MIKU ICHINOSE"`（**居中**）和它下面的路径（小一号、也居中）画进去，
   主行字号由"整行铺满 cols 格"反推；
2. `getImageData` 取 alpha，`>=128` 的像素就是一个字符格；再裁掉四周空白，得到字形掩码
   （1440 宽实测 86×21 格：主行 8 行 + 缝 + 路径 7 行）；
3. 字号刻意**比字格小一圈**：`fontPx = cell × 0.92`，于是字符宽约 0.55 格、左右留出
   约 5.6px 的空隙 —— 之前 `fontPx = cell × 1.26` 时字符挨在一起，串成一片看不清；
4. 每格按**左上打光的明暗**（`shade = 1 - y×0.42 - x×0.16`）挑字符与不透明度：

| 层 | 字符梯度 | 不透明度 |
| --- | --- | --- |
| 字面（第 0 层） | `RAMP_FACE = @ # % & $ * +` —— 最淡也是 `+`，字形永远实心 | 0.40~0.84 |
| 暗影（第 1~2 层） | `RAMP_SOFT`，可以一路淡到 `',` | 0.12~0.36，逐层 ×0.6 |
| 路径那行 | 同样只取 `RAMP_FACE` 的前几档 | 0.60（更暗但不虚） |

> **两张字型的坑**：① 字面如果用完整梯度，斜笔画会掉成 `.`，字看起来是空心的 ——
> 所以字面单独一套"最淡也是 `+`"的梯度，明暗交给**颜色深浅**表达；
> ② 暗影层如果又少又远（每层退 2 格），旋转/错位时就成了断断续续的拖影 ——
> 现在**每层只错 1 格左右**（横向由 `DEPTH_STEP` 决定，纵向 0.75 格），是一整条贴着字形的暗带。

**颜色跟着 accent 走**：`readAccent()` 用 `getComputedStyle` 读 `--accent`，
顶栏切强调色或终端跑 `accent red|green|blue` 时（都会派 `accent:changed`）重读一次，
于是字型、侧面、Hero 的 caret 是同一个色。实测切到红是 `rgb(253,79,93)`、
切到蓝是 `rgb(77,157,255)`（直接从画布像素里读出来的）。

### 位置：整组在页面中间

星球 + 文字 + 路径是一整组，**整体垂直居中**（组心在 `0.47h`），水平居中于视口。
`originX / originY / planetCY` 都取整到**整格**，静止时每个字符正好压住一个格子。
竖排预留高度里，星球的半高按 `1.18R` 算（环几乎侧对着看，竖直方向被压扁），
不然环会白白占掉一大块。

### 背景不能和正文抢

上一轮重点修过这个问题（亮背景 + 满屏大字时正文几乎读不出来）。现在字型搬到左上角之后：

1. **整块只有 99×9 格**（约 820×75px 的一条），不再是铺满屏幕的大字；
2. **散字退场**：装配完成后散字整体压暗 55%，不再一直在正文后面抖；
3. **面板加深**：卡片/文件行/页脚等"正文容器"的底色不透明度调高（深色 0.88、浅色 0.95）；
4. **那枚「系统在线」标签给了实底**（`.eyebrow` 深色 `rgba(6,10,15,.78)`、浅色 0.92）——
   它现在正好压在字型上，原来是近乎透明的，字会互相打架。

> 自检办法：直接读 `#bg-canvas` 的像素，算**合成亮度**（`rgb 均值 × alpha`，
> 注意 `getImageData` 给的是非预乘颜色）。

### 调这块踩过的坑

| 坑 | 症状 | 原因 |
| --- | --- | --- |
| 字面铺多种随机字符 | 字形明明是对的，看上去却是噪声 | 眼睛没法把形状各异的字符归成一个笔画 → 字面单独一套"最淡也是 `+`"的梯度 |
| 暗影层太亮 | 和字面糊成一片雾，字形反而看不清 | 侧面不透明度要压到字面的 1/3 上下 |
| 透视太强（焦距 200 格） | 深处几层往画面中心收，字糊成一团 | 焦距给到 900 格（近似正交） |
| 带 `tilt` 又吸附到格 | 整行字被撕开、翻到隔壁行 | 行的剪切超过半格就翻行 → 关掉鼠标跟随时 `tilt` 固定为 0 |
| 模型坐标写 `celly - rows / 2` | 字这儿凸一块、那儿凹一块 | 掩码 86×21，行数是**奇数**，`rows / 2 = 10.5` 让每一行正好压在 `round` 的半格边界上 → 改用 `Math.floor` |
| 字面带一点 `REST_YAW` | 字上出现一排缺口 | `cos(yaw)` 把相邻列压到同一格 → 字面改成严格轴对齐 |
| 一行太长被截断 | 命令字幕跑到屏幕外 | 字幕超过 62 字就截断，窄屏另有短版命令 |

性能：桌面端总字符约 1850 个（目标 950 + 散字），每个一次 `fillText`；
DPR 上限 1.5；页面不可见时暂停；
系统开了「减少动态效果」时只画一帧静态成品，完全不跑 RAF。
