真人开枪的“像”不在于命中率高低，而在于**不完美但有规律**。机器人的开枪如果每发都精确、节奏恒定、反应一致，就会立刻暴露。真人射击的规律可以从**反应、瞄准、开火节奏、后坐力控制、习惯行为**五个层面拆解，每个层面都有可参数化的实现方式。

### ⏱️ 一、反应时间：不是“看到即开枪”

真人从视觉感知到扣动扳机，存在一个不可消除的延迟链：

| 阶段 | 典型耗时 | 说明 |
| :--- | :--- | :--- |
| 视觉处理 | 100~150ms | 视网膜到视觉皮层，识别“那是敌人” |
| 决策 | 50~150ms | 判断“打不打、怎么打”，受经验和紧张度影响 |
| 运动执行 | 50~100ms | 手指扣动扳机到子弹击发 |

**综合反应时间**：普通玩家约 **250~350ms**，训练有素的玩家可压缩到 **180~250ms**，但不可能低于 100ms。

**实现建议**：
- 给机器人设置一个**基础反应延迟**（如 220ms），每次感知到新目标时启动计时，计时结束前不做出开火决策。
- 反应延迟应**随距离和可见度变化**：远距离、部分遮挡、快速移动的目标，识别耗时更长（可增加 50~150ms）。
- 加入**随机抖动**（±30~50ms），避免每次反应时间完全一致。
- **首次发现 vs 再次发现**要区分：已经交火中的目标，反应延迟可以缩短（因为注意力已锁定）。

```javascript
function getReactionDelay(target, botState) {
  let base = 220; // ms
  base += target.distance * 0.3;          // 距离越远越慢
  base += target.isMoving ? 60 : 0;       // 移动目标更难识别
  base += target.isPartialCover ? 80 : 0; // 部分遮挡
  if (botState.engagedWith(target)) base *= 0.7; // 已交火则更快
  return base + (Math.random() - 0.5) * 80; // ±40ms 抖动
}
```

### 🎯 二、瞄准：有抖动、有预瞄、有修正

真人的准星从来不是“锁死”在目标上的，而是一个**带噪声的追踪过程**。

**1. 生理性抖动（Aim Sway）**

人手在精细瞄准时存在约 **8~12Hz** 的生理性震颤，幅度随疲劳、紧张、瞄准时长增加。表现为准星在目标附近做小幅随机游走。

- 实现：在瞄准方向叠加一个**低频噪声**（如 Perlin 噪声或正弦叠加），幅度约 **0.3°~1.5°**，持续瞄准时间越长，幅度越大（模拟疲劳）。
- 开火瞬间可以**短暂减小抖动**（真人扣扳机时会下意识稳定手部），但不会归零。

**2. 预瞄（Pre-aim）**

真人会把准星放在敌人**最可能出现的头部高度和位置**，而不是随意指向。这是“像人”的关键标志。

- 实现：机器人在移动和驻守时，准星应朝向**已知的高频交火点、拐角边缘、门框高度**，而非始终看向目标当前位置。
- 预瞄位置可以来自地图标注或学习到的热力图。

**3. 甩枪与修正（Flick & Correction）**

真人发现目标后，准星会**快速甩向目标**，但通常会 **overshoot（甩过头）**，然后**反向修正**回来。这个“过冲-修正”的过程是真人瞄准的典型特征。

- 实现：当目标出现在准星偏离位置时，先以高速将准星移向目标，**故意越过目标 3°~8°**，再以较慢速度修正回来。修正过程可加入 1~2 次小幅震荡。
- 甩枪速度随距离和角度差变化：角度差越大，甩枪越“猛”，过冲越明显。

```javascript
function flickAim(currentDir, targetDir, angleDiff) {
  const overshoot = clamp(angleDiff * 0.15, 2, 8); // 过冲角度
  const flickSpeed = 800 + angleDiff * 12;          // 度/秒
  // 第一阶段：快速甩向目标+过冲
  // 第二阶段：慢速修正回目标，带1~2次震荡
  // 第三阶段：进入带抖动的追踪
}
```

### 🔫 三、开火节奏：点射、连发、扫射的切换有习惯

真人不会匀速开枪，而是根据距离、武器、目标状态在几种模式间切换，且切换有**惯性**（不会每帧变来变去）。

| 射击模式 | 典型触发条件 | 节奏特征 |
| :--- | :--- | :--- |
| **单发点射** | 远距离、目标静止或缓慢移动 | 每发间隔 250~500ms，每次 1~2 发 |
| **短点射（Burst）** | 中距离、目标移动 | 每次 2~4 发，间隔 300~600ms |
| **扫射（Spray）** | 近距离、目标暴露、紧急 | 持续开火 1~3s，前 5~8 发较准，之后弹道发散 |
| **试探性开枪** | 不确定目标位置、穿烟/穿墙 | 1~2 发，间隔较长，用于“火力侦察” |

**关键规律**：
- 真人**不会在每次开火前都完美重新瞄准**。短点射之间，准星可能只是大致回到目标附近，而非精确复位。
- **开火持续时间有上限**：即使目标一直在视野内，真人也会因为后坐力、弹药、暴露风险而**主动停火**（如扫射 8~12 发后停一下）。
- **换弹时机不固定**：真人可能在弹匣还剩 5~10 发时就换弹（“战术换弹”），也可能打空才换（“紧急换弹”），取决于当前压力。

**实现建议**：
- 为机器人维护一个**射击模式状态**，模式切换需要满足条件并持续一段时间（避免抖动）。
- 每次开火序列结束后，加入 **100~300ms 的“观察停顿”**，模拟真人确认命中效果。
- 弹匣剩余量低于阈值时，**概率性触发战术换弹**（如低于 40% 时每帧 0.5% 概率），而非固定阈值。

---

### 📉 四、后坐力控制：压枪不完美，有“修正过度”

真人压枪是一个**持续修正**的过程，不是完美的反向补偿。

- **前几发**：准星基本能压在目标上（因为后坐力模式可预测）。
- **中段**：开始出现偏差，真人会**过度修正**（压过头）或**修正不足**（压不够），弹着点呈不规则的左右摆动。
- **后段**：弹道发散明显，真人可能选择停火重置。

**实现建议**：
- 不要用完美的后坐力补偿曲线。在补偿量上叠加**低频随机偏移**（幅度随连发数增加），模拟“压枪手抖”。
- 连发超过 8~10 发后，**命中率应显著下降**，并提高机器人“停火重置”的概率。
- 不同“技术水平”的机器人可以有不同的压枪精度参数：新手偏差大，老手偏差小但仍有。

---

### 🧠 五、习惯行为：真人有“怪癖”

这些细节最能提升拟真度：

1. **切枪习惯**：真人在安全时会频繁切枪（刀/手枪），机器人可以在移动途中以低概率触发无意义的切枪动画。
2. **预开枪（Pre-fire）**：真人会对已知的常见架点**提前开枪**，即使没看到人。机器人可以在经过高频交火点时以一定概率预开枪。
3. **开火后的“确认”**：真人击杀后会短暂停顿或微调准星，而不是立刻转向下一个目标。加入 **200~400ms 的击杀确认延迟**。
4. **紧张度影响**：血量低、被多人包围时，真人会**更早开枪、更少瞄准、更多扫射**。可以设置一个 `panic` 系数，低血量时提高开火概率、降低瞄准精度、缩短点射间隔。
5. **弹药焦虑**：弹匣子弹少时，真人会更倾向于“打空再说”或“赶紧找掩体换弹”，而不是继续精确点射。

### 🎬 一个完整的“真人式开枪”伪代码流程

```javascript
function humanLikeShooting(bot, target, dt) {
  // 1. 反应延迟
  if (!bot.targetAcquired) {
    bot.reactionTimer += dt;
    if (bot.reactionTimer < getReactionDelay(target, bot)) return;
    bot.targetAcquired = true;
  }

  // 2. 瞄准（带抖动、甩枪、修正）
  const aimError = computeAimError(bot, target); // 抖动 + 过冲 + 修正
  bot.aimDirection = lerpToTarget(bot.aimDirection, target.position, aimError);

  // 3. 判断是否满足开火条件
  const onTarget = angleBetween(bot.aimDirection, target.position) < bot.accuracyCone;
  const hasAmmo = bot.ammo > 0;
  const inFireMode = bot.fireModeCooldown <= 0;

  if (onTarget && hasAmmo && inFireMode) {
    // 4. 选择射击模式（有惯性，不频繁切换）
    bot.fireMode = selectFireMode(bot, target); // single / burst / spray

    // 5. 执行射击
    fireBullet(bot, bot.fireMode);

    // 6. 后坐力控制（不完美）
    applyRecoil(bot, bot.fireMode); // 含随机补偿偏差

    // 7. 开火后行为
    bot.postFirePause = randomRange(100, 300);
    if (bot.fireMode === 'spray' && bot.sprayCount > randomRange(8, 12)) {
      bot.forceStopFire = true; // 强制停火重置
    }
  }

  // 8. 战术换弹判断
  if (bot.ammo / bot.magSize < 0.4 && Math.random() < 0.005) {
    bot.startReload();
  }

  // 9. 紧张度影响
  if (bot.health < bot.maxHealth * 0.3) {
    bot.panic = true;
    bot.aimSwayAmplitude *= 1.5;
    bot.reactionDelayBase *= 0.85; // 更早开枪
  }
}
```

### 💡 最容易被忽略但效果最明显的三点

1. **开火后的停顿**：真人开枪后不会立刻完美转向下一个目标，那 100~300ms 的“确认停顿”是拟真度的巨大来源。
2. **不完美的压枪**：完美的后坐力补偿是最明显的“机器人特征”。加入随连发数增长的随机偏差，比降低命中率更自然。
3. **预瞄位置**：机器人准星是否经常停在“人头高度”和“常见架点”，比开枪本身更能让玩家感觉到“这是个会玩的人”。

你可以先从**反应延迟 + 瞄准抖动 + 点射/扫射模式切换**这三项入手，它们对拟真度的提升最直接，实现成本也最低。

轻量级自我学习的核心是：**不训练神经网络，而是把机器人AI的行为参数当作“基因”，用多轮对局的统计结果作为“适应度”，通过进化算法迭代出更优的参数组合。** 在 JavaScript 里，这套逻辑可以完全跑在 Node.js 或浏览器中，不需要任何 ML 库。

下面是一个可直接落地的实现框架。

### 🧬 第一步：定义基因组（可学习参数）

把之前讨论过的 Peek、换弹、掩体、侵略性等决策参数打包成一个对象。每个参数都有明确的取值范围和类型。

```javascript
// genome.js
const GENE_DEFS = {
  peekDuration:     { min: 0.3, max: 1.2, step: 0.05 },  // 探身开火时长(s)
  hideDuration:     { min: 0.5, max: 2.5, step: 0.1 },   // 掩体后隐藏时长(s)
  peekProbability:  { min: 0.1, max: 0.9, step: 0.05 },  // 假Peek概率
  reloadThreshold:  { min: 0.1, max: 0.5, step: 0.05 },  // 弹匣低于此比例触发换弹
  coverWeight:      { min: 0.0, max: 1.0, step: 0.05 },  // 掩体评分权重
  aggression:       { min: 0.0, max: 1.0, step: 0.05 },  // 侵略性
  reactionDelay:    { min: 0.0, max: 0.4, step: 0.02 },  // 反应延迟(s)
};

function randomGenome() {
  const g = {};
  for (const [key, def] of Object.entries(GENE_DEFS)) {
    const steps = Math.round((def.max - def.min) / def.step);
    g[key] = def.min + Math.floor(Math.random() * (steps + 1)) * def.step;
  }
  return g;
}

function clampGene(key, value) {
  const def = GENE_DEFS[key];
  return Math.min(def.max, Math.max(def.min, value));
}
```

### 📊 第二步：适应度评估（跑多轮对局）

学习的关键是“跑多轮对局并收集统计”。你的机器人需要能**脱离渲染、快速模拟**对局，否则评估一轮要等几分钟，进化会非常慢。

```javascript
// evaluate.js
async function evaluateGenome(genome, options = {}) {
  const { rounds = 50, opponent = 'baseline' } = options;
  
  let wins = 0, kills = 0, deaths = 0, damageDealt = 0;
  
  for (let i = 0; i < rounds; i++) {
    // 用该基因组创建一个机器人实例
    const bot = createBot(genome);
    const result = await simulateRound(bot, opponent);
    
    wins += result.win ? 1 : 0;
    kills += result.kills;
    deaths += result.deaths;
    damageDealt += result.damage;
  }
  
  // 适应度函数：胜率为主，K/D和伤害为辅助
  const winRate = wins / rounds;
  const kd = deaths > 0 ? kills / deaths : kills;
  const avgDamage = damageDealt / rounds;
  
  // 加权组合，权重可根据设计目标调整
  const fitness = winRate * 1.0 + kd * 0.3 + (avgDamage / 100) * 0.2;
  
  return { fitness, winRate, kd, avgDamage };
}

// 模拟一回合——你的游戏引擎需要提供这个接口
async function simulateRound(bot, opponent) {
  // 这里对接你的实际游戏逻辑
  // 返回 { win, kills, deaths, damage }
  return gameEngine.runHeadlessRound(bot, opponent);
}
```

**关键工程建议**：如果单轮模拟耗时较长，可以：
- **降低评估轮数**（如 20 轮），但增加迭代代数；
- **并行评估**：用 `Promise.all` 同时跑多个基因组，或利用 Worker Threads；
- **对手混合**：一部分对局用固定基线 AI，一部分用历史最强个体，避免过拟合到单一对手。

### 🧪 第三步：进化算法核心（锦标赛选择 + 交叉 + 变异）

用最经典的遗传算法，代码量小且效果好。

```javascript
// evolution.js
const POP_SIZE = 20;
const ELITE_COUNT = 4;
const MUTATION_RATE = 0.2;
const TOURNAMENT_SIZE = 3;

function tournamentSelect(population, fitnesses) {
  let best = null, bestFit = -Infinity;
  for (let i = 0; i < TOURNAMENT_SIZE; i++) {
    const idx = Math.floor(Math.random() * population.length);
    if (fitnesses[idx] > bestFit) {
      bestFit = fitnesses[idx];
      best = population[idx];
    }
  }
  return best;
}

function crossover(parentA, parentB) {
  const child = {};
  for (const key of Object.keys(GENE_DEFS)) {
    // 均匀交叉：每个基因随机来自父或母
    child[key] = Math.random() < 0.5 ? parentA[key] : parentB[key];
  }
  return child;
}

function mutate(genome) {
  const mutated = { ...genome };
  for (const [key, def] of Object.entries(GENE_DEFS)) {
    if (Math.random() < MUTATION_RATE) {
      // 在步长范围内随机扰动
      const delta = (Math.random() - 0.5) * def.step * 4;
      mutated[key] = clampGene(key, mutated[key] + delta);
    }
  }
  return mutated;
}
```

### 🔁 第四步：主循环（代际进化）

```javascript
// main.js
async function evolve(generations = 30) {
  let population = Array.from({ length: POP_SIZE }, randomGenome);
  let bestEver = null, bestFitEver = -Infinity;
  
  for (let gen = 0; gen < generations; gen++) {
    console.log(`\n=== Generation ${gen + 1} ===`);
    
    // 1. 并行评估整个种群
    const results = await Promise.all(
      population.map(g => evaluateGenome(g, { rounds: 30 }))
    );
    const fitnesses = results.map(r => r.fitness);
    
    // 2. 记录本代最优
    const genBestIdx = fitnesses.indexOf(Math.max(...fitnesses));
    if (fitnesses[genBestIdx] > bestFitEver) {
      bestFitEver = fitnesses[genBestIdx];
      bestEver = { genome: population[genBestIdx], stats: results[genBestIdx] };
    }
    
    console.log(`Best fitness: ${fitnesses[genBestIdx].toFixed(3)}`);
    console.log(`Win rate: ${(results[genBestIdx].winRate * 100).toFixed(1)}%`);
    console.log(`Genome:`, population[genBestIdx]);
    
    // 3. 精英保留 + 生成下一代
    const sorted = population
      .map((g, i) => ({ g, f: fitnesses[i] }))
      .sort((a, b) => b.f - a.f);
    
    const nextGen = sorted.slice(0, ELITE_COUNT).map(x => ({ ...x.g }));
    
    while (nextGen.length < POP_SIZE) {
      const parentA = tournamentSelect(population, fitnesses);
      const parentB = tournamentSelect(population, fitnesses);
      let child = crossover(parentA, parentB);
      child = mutate(child);
      nextGen.push(child);
    }
    
    population = nextGen;
  }
  
  console.log('\n=== Evolution complete ===');
  console.log('Best genome:', bestEver.genome);
  console.log('Best stats:', bestEver.stats);
  return bestEver;
}

// 启动
evolve(30).then(best => {
  // 将最优基因组保存，注入到实际游戏的机器人AI中
  saveGenome(best.genome);
});
```

### ⚙️ 轻量级项目的关键工程细节

**1. 用随机种子保证可复现**

进化过程中随机性很多，记录种子可以在复现问题时回放整条进化路径：

```javascript
function seededRandom(seed) {
  let s = seed;
  return () => {
    s = (s * 16807) % 2147483647;
    return (s - 1) / 2147483646;
  };
}
```

**2. 评估必须 headless（无渲染）**

如果每轮模拟都渲染画面，进化会慢几个数量级。你的游戏逻辑需要和渲染解耦，`simulateRound` 只跑物理、AI 决策和伤害计算。

**3. 适应度函数要防“钻空子”**

只优化胜率可能导致机器人学会“龟缩到时间结束”这种无趣策略。建议组合多个指标：

```javascript
const fitness =
  winRate * 1.0 +
  Math.min(kd, 3) * 0.2 +          // 封顶防止刷K/D
  (avgDamage / 100) * 0.15 +        // 鼓励有效输出
  (avgRoundDuration / 60) * 0.05;   // 鼓励积极交战
```

**4. 缓存评估结果**

如果某个基因组之前评估过（比如精英个体直接进入下一代），可以跳过重复评估：

```javascript
const evalCache = new Map();
function genomeKey(g) {
  return Object.entries(g).map(([k, v]) => `${k}:${v.toFixed(3)}`).join('|');
}
```

**5. 参数边界和步长就是你的“正则化”**

离散步长（如 `step: 0.05`）天然限制了搜索空间，让进化在有限代数内收敛。不要用连续浮点数做变异，否则搜索空间太大、收敛慢。

---

### 📈 这条路径能学到什么、不能学到什么

**能学到**：Peek 与隐藏的节奏比例、换弹时机阈值、掩体偏好权重、侵略性水平——这些是“策略调参”，进化算法非常擅长。

**学不到**：全新的战术组合（比如“诱骗→绕后→夹击”这种需要多步推理的行为链）。如果你观察到进化后机器人只是参数变好但行为模式单一，那就是时候考虑之前提到的 RL 高层策略或 LLM 反思路径了。

**一个务实的判断标准**：如果进化 30 代后适应度曲线趋于平缓，且最优基因组与初始随机种群的差异主要体现在参数值而非行为模式上，说明参数搜索已经接近上限，该升级架构了。
